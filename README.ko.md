**Bug Reporting in One Shot.**

브라우저에서 캡처해 트래커로 바로 보내는 오픈소스 버그 리포팅 도구입니다.

BugShot은 스크린샷·녹화·콘솔/네트워크 로그·사용자 액션·환경 정보와 CSS 수정 전후
diff까지 캡처해 Jira·GitHub·Linear·Notion·GitLab·Asana·ClickUp 또는 Slack용
리포트로 만드는 Chrome 사이드 패널입니다.

BugShot 계정도, 호스팅 워크스페이스도 없습니다. 캡처 데이터는 BugShot 서버를
거치지 않습니다. BugShot은 유료 플랜 계획 없이 무료입니다. 운영할 캡처 백엔드도,
과금할 사용량도, 회수해야 할 호스팅 비용도 없기 때문입니다.

[Chrome 웹스토어에서 설치](https://chromewebstore.google.com/detail/bugshot/ohakhekagkodklkickemonmifdcbhmig)
· [문서 보기](https://bug-shot.com/ko/docs)
· [개인정보](#개인정보)

## 눈에 보이는 버그를 바로 처리할 수 있는 리포트로

1. **문제를 캡처합니다** — 요소를 고르거나, 스크린샷을 찍거나, 화면을 녹화합니다.
2. **증거를 모읍니다** — 환경·콘솔·네트워크·액션 로그가 자동으로 첨부됩니다.
3. **업무가 이뤄지는 곳으로 보냅니다** — 리포트를 검토한 뒤 트래커나 Slack으로
   직접 제출합니다.

## 만든 이유

저는 프로덕트 디자이너입니다. UI 버그를 발견하면 DevTools에서 페이지를 검사해 CSS를
고치고, 스크린샷을 찍고, Jira로 옮겨가 이슈에 수정 전후 표를 일일이 만들었습니다.

그 과정이 너무 번거로워 모든 작업을 한 화면에서 끝내고, 결과를 제가 원하는 양식으로
Jira에 보내는 도구를 만들었습니다.

회사에서 사용하다 보니 QA 팀이 전반적인 버그 리포팅도 할 수 있게 해달라고 요청했습니다.
그때부터 스크린샷과 녹화가 들어갔고, 이어서 네트워크 요청·콘솔 로그처럼 버그 재현에
필요한 증거가 확장되기 시작했습니다. BugShot은 사내 QA 팀의 업무 도구로 자리 잡았고,
저도 지금까지 매일 사용하며 개선하고 있습니다.

CSS diff 표를 손으로 만들지 않으려고 시작한 도구가 첫 3개월 동안 지금의 제품으로
커졌습니다.

## 구조로 지키는 개인정보

버그 리포트에는 프로덕션 세션의 가장 민감한 단면이 담길 수 있습니다. 스크린샷 속
고객 데이터, 네트워크 트래픽의 토큰, 콘솔의 내부 식별자, 폼에 입력한 내용이
그 예입니다.

저는 BugShot이 그 데이터를 받아 저장하는 또 하나의 서버가 되기를 원하지 않았습니다.
핵심 데이터 경로는 다음과 같습니다.

```text
사용자 브라우저 ───────────────────→ 사용자의 트래커 또는 Slack
       │
       ├── AI 사용 시 ─────────────→ 사용자가 선택한 LLM endpoint
       │
       ├── OAuth 교환만 ───────────→ BugShot OAuth 프록시
       │
       └── 익명 사용량 이벤트 ─────→ PostHog (BugShot 소유 프록시 도메인 경유)
```

스크린샷·녹화·로그·CSS 변경·첨부 파일·리포트 본문은 확장 프로그램 안에서 조립되어
연결한 대상으로 직접 전송됩니다. Jira·GitHub·Notion·Asana·ClickUp·Slack은 BugShot이
운영하는 OAuth 프록시가 인가 코드 교환과 토큰 갱신을 중계하고, Linear·GitLab은 PKCE로
토큰을 직접 교환합니다. 캡처 데이터는 프록시를 지나지 않으며, 익명 분석에는 캡처나
리포트 내용이 포함되지 않습니다. 이 익명 이벤트는 BugShot이 소유한 도메인
`in.bug-shot.com`을 통해 나가지만, 이 도메인의 DNS 레코드는 PostHog Cloud를 곧바로
가리킵니다 — 광고·DNS 차단기가 집계를 조용히 떨어뜨리지 않게 하려는 것이고, 이
경로에도 BugShot 서버는 없습니다.

이 구조에는 의도적인 대가가 있습니다. BugShot 계정, 팀 워크스페이스, 클라우드 동기화,
서버 측 캡처 데이터 처리를 제공하지 않습니다. 개인정보 관련 주장을 믿는 대신 구조를
직접 확인할 수 있도록 프로젝트 전체를 오픈소스로 공개했습니다.

[BugShot이 보내는 모든 외부 요청 보기](docs/privacy.ko.md#3-외부-전송).

## 시작하기

**Chrome 116 이상이 필요합니다.** Side Panel API를 지원하는 다른 Chromium 계열
브라우저(Edge, Brave, Arc)에서도 동작할 것으로 보이지만, 테스트된 것은 Chrome입니다.
Firefox·Safari 빌드는 없습니다. UI 전체가 Chrome MV3 사이드 패널이고 두 브라우저는
그 API를 구현하지 않습니다.

1. **설치** — [Chrome 웹스토어](https://chromewebstore.google.com/detail/bugshot/ohakhekagkodklkickemonmifdcbhmig)에서 설치합니다.
2. **패널 열기** — 툴바 아이콘을 클릭하거나 `Cmd/Ctrl+Shift+E`를 누릅니다.
3. **전송 대상 연결** — *연동* 탭에서 트래커나 Slack을 연결합니다.
4. **캡처** — 요소 스타일을 편집하거나, 요소·영역을 캡처하거나, 화면·페이지 전체
   스크린샷을 찍거나, 탭·화면을 녹화합니다. 콘솔·네트워크 로그 탭에서는 캡처 없이
   로그만으로 리포트를 시작할 수도 있습니다.
5. **제출** — 증거를 검토한 뒤 완성된 리포트를 보냅니다.

전체 과정은 [퀵스타트 가이드](https://bug-shot.com/ko/docs/quick-start)에 있습니다.

## 기능

### 🎨 스타일링

설명하기 전에 눈으로 먼저 고칩니다.

- **요소 선택기** — 마우스를 올리면 하이라이트되고, 클릭하면 페이지의 어떤 DOM 요소든 선택됩니다. 중첩되고 스타일이 겹겹이 얹힌 요소에서도 동작합니다.
- **DOM 트리 탐색** — 마우스로 닿지 않는 요소가 있나요? 다이얼로그에서 실시간 DOM 트리를 훑어 노드를 직접 고르거나, 부모·첫 자식으로 이동할 수 있습니다. 래퍼나 오버레이에 가려진 요소를 위한 기능입니다.
- **실시간 CSS 편집** — 레이아웃·여백·크기·색상·타이포그래피·테두리 등을 구조화된 필드로 편집하거나, 문법 강조가 되는 CSS 코드 편집기로 전환해 원본 CSS를 직접 수정합니다(임의 속성, `!important` 가능). 편집기에는 요소의 현재 스타일이 미리 채워지고(4방향 롱핸드는 숏핸드로 병합), 자동완성과 인라인 색상 스와치가 붙습니다. 변경은 실제 페이지에 즉시 적용되므로 정확한 수정안을 그 자리에서 맞춰볼 수 있습니다.
- **클래스·텍스트 편집** — 요소의 클래스 목록이나 노출 텍스트를 실시간으로 고치면, 그 변경도 스타일 diff와 함께 기록됩니다.
- **디자인 토큰 인식** — `var()` 체인을 따라가 계산된 값 대신 토큰 이름(예: `--color-primary`)을 보여줍니다. 리포트가 팀의 디자인 시스템 언어로 쓰입니다.
- **수정 전후 diff** — 모든 변경이 추적되어 이슈에 before → after 표로 렌더링되고, 감싼 다이얼로그·표의 행까지 넓혀 찍은 편집 전후 스크린샷이 함께 담겨 한눈에 어느 항목인지 알아볼 수 있습니다. 개발자는 어떤 속성을 바꿔야 하는지 정확히 봅니다. 그 전후 이미지에는 **각각 주석을 달 수 있어** 한 프레임에 여러 요소가 담겨도 어디가 문제인지 짚어 줄 수 있고, 주석을 지우면 처음 캡처한 원본으로 돌아갑니다. 여러 요소에 걸친 편집도 쌓여서 제출 전까지 보존됩니다.

### 📸 캡처

화면에 있는 그대로를 잡아 표시를 남깁니다.

- **요소 캡처** — 요소를 클릭하면 그 요소만 깔끔하게 잘라 스크린샷으로 만듭니다. DOM 셀렉터는 이슈 환경 정보에 자동으로 들어갑니다.
- **iframe 안에서도 동작** — 선택기가 임베드된 프레임 안쪽 한 단계까지 닿습니다. cross-origin도 포함입니다.
- **영역 캡처** — 화면의 임의 영역을 드래그해 정확한 조각만 잘라냅니다.
- **화면 캡처** — 드래그 없이 보이는 뷰포트 전체를 한 번에 잡습니다.
- **페이지 전체 캡처** — 스크롤하며 페이지 전체를 하나의 긴 스크린샷으로 이어 붙입니다. fixed·sticky 헤더는 한 번만 찍히고, 지나치게 긴 페이지는 한계에서 멈추며 안내가 뜹니다.
- **어노테이션** — 첨부 전에 화살표·자유 펜·텍스트·도형·형광펜으로 표시를 남깁니다. 캔버스를 확대(fit-width에서 400%까지)하고 이동할 수 있어 긴 페이지 전체 캡처에서도 세부를 짚을 수 있고, 완성된 이미지는 항상 원본 해상도로 첨부됩니다.
- **본문 삽입 증거** — 영역을 추가로 캡처하거나 이미지를 본문 섹션에 붙여넣기·드롭·추가한 뒤, 그 자리에서 어노테이션·복원·삭제할 수 있습니다.

### 🎬 녹화

정지 이미지로 부족할 때는 동작을 녹화합니다.

- **탭 녹화** — 현재 탭을 최대 60초까지 녹화해 MP4로 인코딩합니다(MP4 미지원 환경은 WebM 폴백).
- **화면 녹화** — 시스템 선택기로 임의의 창이나 전체 화면을 최대 60초까지 녹화합니다.
- **녹화 중 그리기** — 미니 툴바(펜·박스·형광펜, 최대 5색·좁은 패널에서는 축소, 굵기 3단계)로 탭·화면 녹화 도중 페이지에 표시를 남깁니다. 자유 곡선은 그린 순서대로 꼬리부터 약 3초에 걸쳐 사라지고, 박스는 한 번에 사라집니다. 어느 쪽이든 영상에 그대로 구워집니다.
- **30초 리플레이** — 옵트인으로 켜두면 **직전 30초**를 MP4로 상시 보관합니다. 페이지 이동을 가로질러 되돌아보므로 버그를 발견한 *뒤에도* 잡을 수 있습니다. 미리 녹화 버튼을 누를 필요가 없습니다.
- **제출 전 구간 자르기** — 탭 녹화·화면 녹화·30초 리플레이 어느 쪽이든 멈추면 자르기 화면이 열립니다. 손잡이를 끌어 버그 순간만 남기면 첨부되는 콘솔·네트워크·액션 로그도 같은 구간으로 좁혀집니다. 손잡이를 건드리지 않으면 재인코딩이 일어나지 않고, 재인코딩에 실패해도 원본 영상이 그대로 첨부됩니다.

### 📋 로그

재현에 필요한 맥락을 백그라운드에서 대신 모읍니다.

- **네트워크·콘솔 로그** — 패널이 열려 있는 동안 자동으로 수집되어 이슈에 첨부됩니다. **WebSocket 프레임**과 **cross-origin iframe**(결제 위젯·임베드)의 로그까지 포함하며, 전부 origin으로 필터링됩니다.
- **액션 로그** — 클릭·텍스트 입력·페이지 이동·단축키·체크박스/라디오 토글·드롭다운 선택·드래그 앤 드롭이 단계별 재현 과정으로 기록됩니다. 민감한 값은 필드 라벨과 값 형태(이메일, 긴 숫자열) 양쪽으로 마스킹되고, 리치 텍스트 편집기 내용은 아예 기록하지 않습니다.
- **본문에 로그 넣기** — 콘솔이나 네트워크 항목 하나를 골라 증상을 설명하는 자리에 코드 블록으로 넣습니다(JSON은 정렬·강조 처리). 첨부 파일은 내려받아야 열리지만, 이건 이슈 안에서 바로 읽힙니다.
- **재현 환경의 API 호스트** — 네트워크 로그 중 페이지와 같은 도메인을 쓰는 호스트가 재현 환경에 자동으로 채워집니다. 첨부를 내려받지 않아도 어느 서버를 봐야 하는지 바로 알 수 있습니다. 평범한 행이라 마음에 안 들면 고치거나 지우시면 됩니다.
- **로그 뷰어** — **영상과 동기화된 타임라인**을 갖춘 독립 실행 `logs.html` 리포트입니다. 콘솔·네트워크·액션 항목을 클릭하면 녹화의 해당 순간으로 점프합니다. **리포트 탭**(이슈 본문 미리보기 + 마크다운 복사)과 탭별 내보내기(HAR, 콘솔/액션 JSON)도 함께 들어 있습니다.

세 가지 로그는 요소 스타일 편집을 제외한 모든 캡처에 함께 따라가고, logs.html 번들 전체는 제출 전 스위치 하나로 끌 수 있습니다(이미 저장된 이슈에서도 토글 가능).

### 🤖 AI

- **AI 초안** — BYOK(Bring Your Own Key)로 OpenAI·Anthropic·Gemini 등을 쓰고, 키가 없으면 Chrome 내장 AI로 폴백합니다. 캡처(스타일·스크린샷·로그 요약)를 바탕으로 제목과 본문을 한 번에 작성합니다. AI가 관련 에러 로그를 지목하면 실제 콘솔/네트워크 항목이 코드 블록으로 본문에 삽입되는데, 앱이 직렬화한 값이라 로그 내용이 환각될 수 없습니다. 초안을 작성할 언어는 화면 언어와 별개로 고를 수 있습니다.
- **AI 스타일링** — 고칠 내용을 말로 설명하면 AI가 선택한 요소에 CSS를 써 넣고, 페이지에 실시간으로 반영됩니다.
- **재현 과정 자동 채우기** — AI를 연결하면 **기본으로 켜집니다**. 녹화 후 재현 과정 섹션이 액션 로그를 바탕으로 자동 작성되며, 이는 액션 로그가 그 AI로 전송된다는 뜻입니다. 설정 → 이슈 설정 → 기타에서 끌 수 있습니다.

### 📥 이슈 목록·초안

- **제출한 이슈** — 등록한 모든 리포트가 플랫폼 배지와 함께 *이슈 목록* 탭에 남고, 검색과 제출/초안 필터링이 됩니다. 새로고침으로 트래커의 현재 상태를 가져오거나, 패널에서 바로 상태를 바꿔 되돌려 쓸 수 있습니다. Slack으로 공유한 리포트는 **나중에 트래커 이슈로 승격**할 수 있고, 원래 Slack 스레드에는 새 이슈 URL이 답글로 달립니다.
- **초안** — 아직 등록할 준비가 안 됐다면 초안으로 저장해 두었다가 다시 열어 어떤 필드든 고친 뒤 제출하세요.

### 🔗 연동

OAuth 또는 토큰으로 연결합니다. 모든 **트래커**가 전송 대상 선택과 첨부 파일 업로드를
지원합니다. 담당자는 Notion을 제외한 전 트래커에서, 라벨 선택은 GitHub·Linear·GitLab에서만
됩니다. **Slack**은 트래커가 아니라 메신저라 채널이나 DM으로 보냅니다.

*연동* 탭에서 기본값을 한 번 정해두면 — 전송 대상(프로젝트·저장소·팀·워크스페이스)과
**담당자**·CC(참조)·라벨·이슈 타입 — 새 리포트가 매번 미리 채워진 채로 열립니다. 마지막에 지정한
담당자가 기본값보다 우선하므로 흔한 경우는 클릭 한 번으로 끝납니다.

| 플랫폼 | 인증 | 특징 |
|---|---|---|
| **Jira** | OAuth 3LO / API 토큰 | 프로젝트 메타데이터, 스프린트 선택, 첨부 파일 자동 업로드 |
| **GitHub** | OAuth / PAT | 저장소, 라벨, 담당자, 파일 업로드 |
| **Linear** | OAuth PKCE / API 키 | 팀, 프로젝트, 라벨, 우선순위 |
| **Notion** | OAuth / 내부 토큰 | 데이터베이스 선택, 상태·선택 속성 |
| **GitLab** | OAuth PKCE / PAT | gitlab.com + self-managed 인스턴스 |
| **Asana** | OAuth / PAT | 워크스페이스, 프로젝트, 담당자 |
| **ClickUp** | OAuth / API 토큰 | 워크스페이스 → 스페이스 → 리스트, 담당자 |
| **Slack** | OAuth (user token) | 채널/DM, @멘션, 제목 + 스레드 상세·파일 |

## 개발

```bash
pnpm install
pnpm dev          # 개발 서버 (@crxjs/vite-plugin 기반 HMR)
pnpm build        # 프로덕션 빌드 → dist/ (build:log-viewer를 먼저 실행)
pnpm build:log-viewer  # 로그 뷰어 번들만 (build/build:store/build:e2e가 자동 포함)
pnpm build:store  # 스토어 업로드 빌드 (manifest key 제거)
pnpm preview      # 프로덕션 빌드 미리보기
pnpm typecheck    # 타입 체크만
pnpm test         # 단위 테스트 (Vitest)
pnpm test:watch   # 단위 테스트 watch 모드
pnpm build:e2e    # e2e 전용 빌드 → dist-e2e/ (테스트 픽스처 — 로드·업로드 금지)
pnpm test:e2e     # Playwright e2e 스위트 (build:e2e 선행 필요)
pnpm sync:agents  # Codex 미러 재생성 (AGENTS.md, .agents/skills/)
```

`chrome://extensions`에서 개발자 모드로 `dist/`를 압축 해제된 확장으로 로드하세요.
e2e 스위트는 `e2e/`에 있고, 커버리지와 함정은 [`e2e/README.md`](e2e/README.md)를 참고하세요.
패치 환영합니다. 기준 브랜치·CI 검사 항목·머지되지 않는 변경은
[`CONTRIBUTING.md`](CONTRIBUTING.md)에 정리돼 있습니다.

### 직접 빌드해서 확인하기

개인정보 관련 주장을 믿지 말고 소스에서 빌드해 네트워크 탭을 직접 보세요.

```bash
git clone https://github.com/SinhyeokKang/bugshot-2.git
cd bugshot-2
pnpm install
cp .env.example .env.local   # 선택 — 아래 설명 참고
pnpm build
```

그리고 `dist/`를 압축 해제된 확장으로 로드하면 됩니다. `.env.example`의 모든 키는
선택입니다. OAuth client ID가 없으면 OAuth 버튼이 숨겨지고 개인 액세스 토큰으로
플랫폼을 연결하며, PostHog 키가 없으면 분석이 no-op이 됩니다. 즉 `.env.local`을 비운
채로 빌드해도 기능은 온전하고 *동시에* 분석 요청이 하나도 나가지 않습니다.

사이드 패널에서 DevTools를 열어 보이는 것을
[전송 표](docs/privacy.ko.md#3-외부-전송)와 대조해 보세요. 목록 전체에서 BugShot이
운영하는 엔드포인트는 OAuth 토큰 교환 프록시 하나뿐이고, 그것은 code→token 교환만
중계할 뿐 캡처 데이터를 나르지 않습니다.

## 아키텍처

코드베이스를 결정지은 선택들과, 각각이 치른 대가입니다.

**백엔드 없음, 구조적으로.** 데이터 경로에 BugShot 서버가 없습니다. "안 본다"가 아니라
볼 곳이 없습니다. 캡처·로그·리포트 본문은 확장 안에서 조립되어 사용자 자격 증명으로
트래커에 곧장 POST됩니다. BugShot이 운영하는 유일한 엔드포인트는 OAuth code를 token으로
교환하는 Cloudflare Worker인데, client secret을 공개 번들에 실을 수 없기 때문입니다.
Linear와 GitLab은 PKCE라 그것조차 거치지 않습니다. 대가는 실재합니다. 기기 간 동기화도,
팀 워크스페이스도, 서버 사이드 처리도 없습니다. 전부 이 속성을 깨야 가능한 기능이라
만들지 않습니다.

**레코더는 동기 IIFE이고, 그게 빌드를 제약합니다.** 콘솔·네트워크 후크는 페이지의 인라인
스크립트가 돌기 *전에* `document_start`에서 설치돼야 하고, 아니면 첫 에러들은 이미
사라진 뒤입니다. 이건 레코더 청크가 self-contained일 때만 성립합니다. 외부 static import가
하나만 섞여도 async loader로 바뀌어 후크가 너무 늦게 깔립니다. 그래서 throttle 헬퍼를
공유하지 않고 레코더와 사이드 패널에 **의도적으로 중복**해 두었고, `sessionStorage`
플래그 덕분에 사이드 패널이 연결되기도 전부터 로그를 버퍼에 적재합니다.

**페이지 전체 캡처는 세 컨텍스트에 걸쳐 조율됩니다.** 사이드 패널이 전체를 지휘하고,
콘텐츠 스크립트 실행기가 페이지를 스크롤하며, 각 타일은 백그라운드 워커의
`captureVisibleTab`을 거칩니다. 반복되는 `fixed` 헤더와 뒤늦게 나타나는 `sticky` 요소는
타일 사이에 `visibility`로 숨기고 — 캡처 도중 추가되거나 position이 바뀐 요소까지
추적합니다 — 끝나면 원래 스타일과 스크롤 위치를 복원합니다.

**iframe 지원은 한 단계까지이고, 그렇다고 명시합니다.** 선택기는 모든 프레임에 주입되고,
자식은 `postMessage`로 최상위 프레임에 등록하며, 요소는 `selector + frameId` 복합키로
식별됩니다. 등록되지 않은 프레임(2단계 이상 중첩, sandbox)은 조용히 실패하지 않고 명시적
거부 경로를 타 안내 다이얼로그를 띄웁니다. 등록 토큰은 인증 경계가 아니라 상관관계
힌트입니다. 자식이 브로드캐스트하므로 악의적인 부모 페이지가 읽을 수 있습니다. 이는
간과가 아니라 문서화된, 수용된 한계입니다.

**스타일은 디자인 시스템 기준으로 해석됩니다.** CSS 파이프라인은 `var()` 체인을 따라가
계산된 RGB 대신 `--color-primary`를 보고합니다. 이는 백그라운드 워커가 페이지가 준 URL로
cross-origin 스타일시트를 가져온다는 뜻이고, 곧 SSRF 표면입니다. 그래서
[`src/lib/ssrf-guard.ts`](src/lib/ssrf-guard.ts) 뒤에서 동작합니다. http(s)만 허용하고
loopback·사설·link-local·CGNAT·멀티캐스트·IPv6 ULA·IPv4-mapped-IPv6 우회를 전부
거부하며, `credentials: "omit"`, `redirect: "manual"`, 타임아웃, content-type 검사, 크기
상한이 함께 걸립니다. 남은 구멍 하나는 덮지 않고 그 파일에 적어 두었습니다. `fetch`가
DNS를 다시 해석하므로 내부 주소로 resolve되는 호스트명은 정적으로 막을 수 없습니다.
가져온 CSS는 기기 안에서만 쓰입니다.

**8개 트래커 연동이 하나의 어댑터 이음매 뒤에 있습니다.** 플랫폼마다 인증(OAuth 또는
토큰)·필드 스키마·업로드 경로가 다르지만, 리포트 본문은 한 번 만들어 대상별로
렌더링합니다 — 마크다운, Jira ADF, Notion 블록, Slack mrkdwn.

이 중 상당 부분은 단위 테스트가 불가능합니다. DOM 측정·포인터 드래그·캔버스·미디어 API는
실제 브라우저가 필요합니다. 그래서 Vitest가 못 하는 몫을 Playwright 스위트가 지고,
커버리지 지표는 브라우저에 묶인 파일을 의도적으로 분모에서 빼 숫자가 정직한 신호로
남게 합니다.

상세는 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)에 있습니다.

### 왜 모든 사이트 접근 권한을 요구하나

Chrome은 이 권한을 *"모든 웹사이트의 모든 데이터를 읽고 변경"*으로 표시합니다. 설치
다이얼로그에서 가장 겁나는 문장이고, 선택이 아니라 필수입니다. BugShot도 처음엔 optional
버전으로 출시해 런타임에 권한을 요청했지만, 실사용에서 깨져서 접었습니다.
`captureVisibleTab`은 `activeTab` 또는 광역 host permission 위에서만 동작하는데,
`activeTab`은 페이지가 cross-document 네비게이션을 하는 순간 회수되고 프로그램적으로
다시 얻을 방법이 없습니다. 쫓던 버그가 페이지를 이동시키는 순간 — 정확히 그게 필요한
순간에 — 녹화나 30초 리플레이가 그냥 죽어버립니다.

그래서 권한은 광범위합니다. 데이터 경로는 그렇지 않습니다. 이 권한이 여는 모든 동작은
사용자 기기 안에서 일어나고, 위의 전송 표가 기기 밖으로 나가는 것의 전부입니다. 범위를
좁히고 싶다면 Chrome에서 가능합니다 — **확장 프로그램 → BugShot → 사이트 액세스** —
다만 그 범위를 필요로 하는 기능은 그만큼 제한된다는 점을 감안하세요.
