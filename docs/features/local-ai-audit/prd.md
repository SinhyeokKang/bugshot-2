# Chrome 로컬 AI 사용 가능 상태 복구

## 배경

감사 4–6에서 영어 세션 선언과 UI 언어 프롬프트의 불일치, 다운로드 가능한 모델의 사용 불가 처리, 자동 재현 생성의 명시적 중단 미연결을 확인했다. A–C 데이터 보존·접근성 수정은 tasks.md의 별도 배치다.

## 목표

- 다운로드 가능한 기기에서 설정 > AI의 사용자 클릭으로 로컬 모델을 준비한다.
- 준비 중 진행·실패·재시도·완료를 표시하고 준비 후 열린 AI 소비처의 가용성을 갱신한다.
- 지원 언어 선언과 생성 지시를 일치시키고 실제 지원하지 않는 언어를 지원하는 것처럼 표시하지 않는다.
- 중단 클릭이 로컬 prompt를 취소하며, 취소 결과는 사용자 초안에 적용되지 않는다.

## 비목표

모델 선택기·번역 파이프라인·새 원격 서비스·이미지 지원·로컬 모델 저장소/삭제 관리·AI 출력 품질 개선은 추가하지 않는다. 기존 BYOK 우선 정책과 로컬 엔드포인트 capability는 유지한다.

## 사용자 흐름

1. BYOK 미연결 상태의 설정 > AI에서 Chrome AI 상태를 확인한다. 기존 외부 AI 연결 버튼은 유지한다.
2. API 부재/unavailable은 미지원 안내와 재확인, downloadable은 모델 다운로드 버튼, downloading은 진행 중 안내를 표시한다. checking 중 중복 다운로드를 허용하지 않는다.
3. 명시적 클릭의 첫 비동기 작업으로 LanguageModel.create를 호출한다. 모델 다운로드가 필요하며 브라우저가 관리한다는 안내를 버튼 근처에 둔다.
4. 모니터 이벤트가 있으면 실제 진행률, 없으면 불확정 진행을 표시한다. 실패는 안내 후 재시도 가능, 완료되면 준비용 세션을 destroy하고 재확인해 available인 경우에만 생성 버튼을 연다.
5. 앱 재진입·설정 화면 재진입/명시적 재확인으로 외부 다운로드 완료 또는 모델 제거를 반영한다. BYOK 연결로 바뀐 뒤 늦은 로컬 준비 응답은 선택 provider를 되돌리지 않는다.
6. 생성 중 중단하면 native prompt와 결과 적용을 취소한다. 자동 재현 생성은 다운로드를 시작하지 않는다.

## 언어 정책 — 사용자 확정

사용자는 “한국어로 출력을 받아야하는 경우, 그렇게 출력이 되어야 함”이라고 확정했다. 한국어 요청을 영어로 대체해 성공 처리하지 않는다. Chrome이 요청 언어를 지원하지 않으면 생성·다운로드를 막고 해당 언어를 지원하는 외부 AI 연결을 안내한다. 자동 원격 전송이나 새 번역 파이프라인은 추가하지 않는다.

지원되는 출력 언어는 세션 옵션과 프롬프트를 일치시킨다. Chrome compact의 요청 언어는 기존 UI 로케일 기준이며 rich의 독립 aiLanguage 설정과 혼동하지 않는다. 한국어 UI에서도 사용자가 선택한 rich 외부 provider의 출력 언어 계약은 유지한다. 지원 목록은 구현 시 공식 문서와 availability를 확인하고, 한국어 입력 자체의 지원은 약속하지 않는다.

## 성공 기준

상태별 UI, 클릭 유무에 따른 create 호출, native options의 언어/취소 신호, 중복 호출·늦은 응답·완료 후 세션 정리를 mock 기반 단위/jsdom/e2e로 검증한다. 실제 모델 다운로드·한국어 입력 처리·출력 언어는 실제 Chrome 실행으로만 검증했다고 보고한다.
