# Custom Webhook 전송

## 배경

GitHub 이슈 [#236](https://github.com/SinhyeokKang/bugshot-2/issues/236)(`custom connectors`)에서 나온 요청이다. 원문은 *"i want my team to install the chrome extension and issues would come to my server instead of going to these existing locations"* — 팀이 확장을 설치하되 리포트가 기존 8개 플랫폼이 아니라 **자기 서버로 오게** 해달라는 것.

이 요청은 BugShot의 코어 밸류(클라이언트 온리)와 충돌하지 않는다. 오히려 가장 순수한 형태다 — 캡처 데이터가 **사용자 브라우저에서 사용자가 지정한 서버로 직행**하고 BugShot 서버는 어느 경로에도 없다. 요청자도 이슈 템플릿의 Scope check("이 기능은 BugShot 서버에 캡처 데이터를 저장하거나 워크스페이스를 호스팅하지 않는다")를 체크한 상태로 올렸다.

`docs/features/DROPPED.md`를 기능 키워드(webhook·커넥터·connector·self-host·사내·임의 서버)로 grep했고 걸리는 항목은 없다. 다만 **DROPPED.md의 최초 항목이 2026-08-08이라 그 이전 드랍은 grep이 구조적으로 못 잡는다** — 실제로 `docs/features/azure-devops-integration/`이 2026-06-02 기획 → 06-09 삭제(구현 0줄)됐고 사유가 어디에도 없다. 이 기능이 흡수하려는 대상 목록에 Azure DevOps가 들어 있으므로, 착수 전 `git show 032a454f:docs/features/azure-devops-integration/prd.md`로 당시 판단을 복원해 볼 가치가 있다.

레버리지가 이 기능의 진짜 근거다. 8개 플랫폼 밖의 모든 대상 — Redmine·YouTrack·Shortcut·Azure DevOps·사내 자체 트래커 — 을 **어댑터 코드 추가 없이** 흡수한다. 지금까지 플랫폼 하나를 붙일 때마다 `src`에서 70여 파일이 움직였다(ClickUp 기준 74파일). 그 비용을 사용자 쪽 수신 서버로 넘기는 것이다.

## 목표

1. 사용자가 **엔드포인트 URL + 요청 헤더**를 입력해 연결하면, 이슈 제출 다이얼로그에 `Custom Webhook` 탭이 뜨고 기존 8개 플랫폼과 같은 자리에서 제출할 수 있다.
2. **multipart 모드**(기본): 캡처 미디어(스크린샷·영상·`logs.html`·사용자 첨부)를 파일 파트로 실어 **단일 POST**로 보낸다. 본문 마크다운은 `cid:<part-name>`으로 그 파트들을 참조한다. 수신 서버는 **`{key, url}`을 반환해야 하고**, 없으면 제출 실패로 처리한다 — 수신부를 직접 짜는 사람이 상대이므로 계약을 지킬 수 있다.
3. **JSON 템플릿 모드**: 사용자가 요청 바디 모양을 직접 정의한다. 화이트리스트 변수(`{{title}}`·`{{body}}` 등)를 치환해 임의 제3자 훅(Discord·Slack incoming·Zapier·n8n·사내 REST)에 맞춘다. 이 모드는 **2xx만으로 성공**이고 응답 파싱을 하지 않는다 — Discord가 `204 No Content`를 주듯 제3자 훅은 식별자를 돌려주지 않는 게 정상이다.
4. 전송 전에 **바디 크기를 계산해 사용자에게 보여주고**, 실패하면 HTTP status와 응답 본문 앞부분을 노출한다. 무음 실패를 남기지 않는다.
5. 평문 http는 **네트워크 경계 안에서만** 허용한다(loopback·사설망). 공인망 평문은 거부한다.
6. 브라우저가 설정할 수 없는 요청 헤더(`Cookie`·`Host`·`Content-Length`·`Origin` 등)는 **저장 시점에 거부**한다. 조용히 드롭돼 "넣었는데 안 나간다"가 되지 않게 한다.
7. 수신 서버를 짜는 사람이 추측하지 않도록 **계약 문서 + 레퍼런스 수신 서버 스니펫**을 함께 낸다. 계약에는 **멱등 키**가 포함된다 — 타임아웃 후 재시도가 중복 리포트를 만들지 않아야 한다.
8. 진입은 브랜드 로고 그리드가 아니라 **그리드 아래 구분선 + 단독 버튼**이다. 나머지 8개와 성격이 다르다는 걸(사용자가 수신부를 직접 준비한다) 배치로 말한다.

## 비목표 (Non-goals)

- **상태 동기화 없음.** 임의 서버의 티켓 상태를 폴링할 범용 방법이 없다. 이슈 목록에서 `Custom Webhook` 행은 새로고침 후보에서 빠진다(Slack과 같은 처리).
- **JSON 템플릿 모드는 이슈 이력을 남기지 않는다.** 응답에 식별자가 없으니 목록 행을 만들 근거가 없다. 전송 성공 토스트로 끝나고 draft는 기존 규칙대로 정리된다.
- **제출 필드 없음.** 프로젝트·담당자·라벨 같은 선택 필드가 없다. 고를 대상이 서버 쪽에 존재하지 않는다.
- **엔드포인트는 1개.** staging/prod를 나눠 등록하는 N개 모델은 `Accounts`의 "플랫폼당 1계정" 전제를 깨야 해서 이번 스코프 밖이다.
- **OAuth 없음.** 인증은 사용자가 직접 넣는 요청 헤더뿐이다.
- **헤더 값 마스킹 없음.** 기존 8개 연결 폼의 PAT·API 키가 전부 평문 `Input`이라(유일한 `type="password"`는 설정 탭의 LLM 키) 여기만 새 관용구를 만들지 않는다. 대신 **에러 메시지·로그·analytics에 헤더를 절대 싣지 않는다**를 불변식으로 둔다.
- **템플릿 모드의 파일 업로드 없음.** 미디어는 `{{media.*.dataUri}}`를 템플릿에 **직접 쓸 때만** 바디에 들어간다. 영상은 base64가 실질적으로 항상 캡을 넘겨 `dataUri` 변수를 제공하지 않는다(파일명만).
- **재시도·큐 없음.** 실패하면 그 자리에서 실패로 끝난다. 백그라운드 재전송 큐는 만들지 않는다.

## 사용자 시나리오

### A. 자기 서버로 보내는 팀 (요청자 케이스, multipart 모드)

1. 연동 탭 → `플랫폼 추가` → 브랜드 그리드 아래 구분선 밑의 `Custom Webhook` 버튼 → 다이얼로그가 열린다.
1-1. **Endpoint**에 `https://bugs.acme.io/intake` 입력.
2. **Headers**에 `Authorization: Bearer <팀 토큰>` 한 줄 추가.
3. **Format**은 기본값 `multipart` 유지.
4. `연결 테스트` → `X-BugShot-Test: 1` 헤더가 붙은 최소 페이로드가 POST된다. 2xx면 계정이 저장되고 다이얼로그가 닫힌다. 실패하면 status와 응답 본문 앞부분이 토스트로 뜨고 **저장되지 않는다**.
5. 버그를 캡처하고 이슈 제출 → `Custom Webhook` 탭 선택 → 제출.
6. 서버는 `payload` 파트의 JSON과 파일 파트들을 받아 저장하고, 본문의 `cid:screenshot-1.webp`를 자기 스토리지 URL로 치환한다.
7. 서버가 `{"key": "BUG-41", "url": "https://bugs.acme.io/b/41"}`을 돌려주면 이슈 목록 행에 그 키와 링크가 붙는다.

### B. Discord로 보내는 개인 (JSON 템플릿 모드)

1. Endpoint에 Discord 웹훅 URL 입력, Format을 `JSON 템플릿`으로 변경.
2. 템플릿 편집기에 Discord 형식을 직접 작성한다.
   ```json
   { "content": "**{{title}}**\n{{url}}", "embeds": [{ "description": "{{body}}" }] }
   ```
3. 편집기 아래 **미리보기**가 현재 작성 중인 리포트로 치환한 결과와 **바디 크기**를 보여준다.
4. 제출하면 `application/json`으로 그 바디가 그대로 POST된다. 미디어는 실리지 않는다. 2xx면 **전송 성공 토스트**로 끝나고 이슈 목록에는 행을 만들지 않는다(비목표 참조).

### 엣지 케이스

- **multipart 응답에 `key`/`url`이 없다** → **제출 실패**로 처리한다. `markSubmitted`에 도달하지 않으므로 draft·blob이 보존되고, 토스트가 계약(`{key,url}`)을 안내한다. 반쪽 성공 상태를 만들지 않는 게 요지다.
- **JSON 모드 응답이 비어 있다** → 정상. 2xx면 성공이고 응답을 읽지 않는다.
- **응답이 2xx가 아니다** → 실패. `markSubmitted`에 도달하지 않으므로 draft·blob이 보존된다.
- **타임아웃(30초)** → 실패로 처리. 서버가 실제로 받았는지는 알 수 없으므로 토스트 문구에 그 불확실성을 적고, 재시도해도 서버가 멱등 키로 중복을 걸러낼 수 있게 계약에 그 키를 싣는다.
- **바디가 하드캡(25MB)을 넘는다** → 전송 자체를 막고, 무엇이 큰지(영상·첨부) 알려준다. **두 모드 공통**이다 — multipart 조립분도 같은 캡을 받는다. 첨부 picker의 합계 상한(50MB)과 어긋나므로 UI가 그 차이를 설명해야 한다.
- **템플릿이 유효한 JSON이 아니다** → 저장 시점에 거부한다. 제출 시점에 처음 알게 되는 일이 없어야 한다.
- **템플릿이 화이트리스트 밖 변수를 쓴다** → 저장 시점에 거부하고 어떤 변수가 미지의 것인지 알려준다. 조용히 빈 문자열로 치환하지 않는다.
- **브라우저가 설정할 수 없는 헤더를 입력했다** → 저장 시점에 거부. 통과시키면 `fetch`가 조용히 드롭해 원인 불명 문의가 된다(`declarativeNetRequest` 권한이 없어 우회 불가).
- **`http://` 공인망 URL** → 입력 시점에 거부. 사설망·loopback이면 평문 경고 배지를 띄우고 허용한다.
- **Slack 보존 이슈를 Custom Webhook으로 승격** → 지원한다. `promotableTargets`가 slack만 제외하므로 webhook은 자동으로 승격 대상에 들어오고, 이는 의도된 동작이다. 두 모드 모두 단일 POST(atomic)라 "업로드는 성공했는데 생성이 실패"가 구조적으로 불가능하므로 `requireMediaUpload` 가드가 불필요하다(`docs/POSTMORTEM.md` 2026-06-30 분류에서 Jira와 같은 (d) atomic 군). 단 **JSON 모드로 승격하면 목록 행이 안 생기므로** 승격 대상 선택 UI에서 그 차이가 보여야 한다.

## 위험 요소

`/feature` 판정 기준 4개 중 **③ "사정거리가 이름값보다 좁은가"에 걸린다.** 이름은 "Custom Webhook = 임의 대상 전부"인데 비목표가 7개고, 특히 **JSON 템플릿 모드는 BugShot의 핵심 산출물 둘(미디어·추적 링크)이 모두 빠진 축소 경로**다. `anomaly-capture-trigger`를 드랍시킨 축("이름이 약속하는 범위와 실제 작동 창이 어긋난다")과 동형이므로 여기 명시해 둔다. 두 모드를 유지하기로 했으니 **UI가 그 차이를 숨기지 않는 것**이 완화책이다 — Format 선택 시점에 "JSON 템플릿은 미디어를 보내지 않고 이슈 이력을 남기지 않는다"를 그 자리에서 말한다.

나머지 3개 기준은 통과한다: 브라우저·DevTools가 대신하지 않고(①), 페이지에 심는 것이 없으며(②), 순수 함수 유닛 + 목 수신 서버 e2e로 검증 수단이 확실하다(④).

추가로 기록해 두는 것:

- **수요 근거가 단일 요청자다.** 이슈 #236은 이 문서 작성 하루 전 등록됐고 댓글 0·리액션 0이다. 레버리지 논거(어댑터 8개 밖을 전부 흡수)가 수요 논거보다 강하다는 점을 인지하고 진행한다.
- **스코프가 기존 기획 선례 대비 크다.** 최근 두 기획이 신규 파일 0~2개인 데 비해 이 건은 신규 8파일·태스크 14개다. "어댑터는 안 늘지만 **플랫폼 축 배선은 ClickUp과 같은 비용**"이라는 점이 배경의 레버리지 논거와 상쇄된다.
- **9번째 플랫폼이 드러내는 UI 한계.** 제출 다이얼로그 탭 줄이 400px에서 이미 8열 슬랙 0이라 9번째는 가로 스크롤로 전환해야 한다(design.md 참조). 이 기능 탓으로 오인되기 쉬운 선행 픽스다.

## 성공 기준

- 로컬 목 수신 서버(`127.0.0.1`)를 띄운 background 유닛이 multipart 요청의 파트 구성(payload 1 + 파일 N)과 본문의 `cid:` 참조를 검증하고 green이다. e2e는 UI 동선(연결·탭 노출·성공/실패 렌더·draft 보존)을 덮는다 — `panel.route`가 background SW fetch를 못 잡으므로 두 층을 나눈다.
- 템플릿 치환이 순수 함수로 분리돼 유닛 테스트가 따옴표·개행·유니코드가 든 본문에서 유효한 JSON을 만들어냄을 고정한다.
- URL 정책 판정이 순수 함수로 분리돼 공인망 http 거부 / 사설망 http 허용 / https 허용을 유닛으로 고정한다.
- 헤더 이름 판정이 순수 함수로 분리돼 forbidden name 전수를 유닛으로 고정한다.
- 잘못된 토큰·없는 경로·타임아웃 각각에서 **계정이 저장되지 않고** 원인이 사용자에게 보인다.
- multipart 응답에 `{key,url}`이 없으면 제출이 실패하고 draft가 보존된다.
- `docs/privacy.{ko,en}`에 "사용자가 지정한 서버"가 외부 전송 대상으로 등재되고(표 행 + GitLab self-managed식 자유 문단 + §1 자격증명 표 + §5 삭제 안내) 시행일이 갱신된다.
- `pnpm typecheck`·`pnpm test` green.
