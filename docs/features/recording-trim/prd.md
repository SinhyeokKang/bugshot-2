# 녹화 구간 자르기 (Recording Trim)

## 배경

30s Replay로 캡처한 영상은 확정 전에 **자르기 화면**을 거친다 — 앞뒤 불필요한 구간을 잘라내고 버그 순간만 남기며, 함께 첨부되는 console·network·action 로그도 그 구간으로 좁혀진다.

반면 **탭 녹화·화면 녹화**(일반 record 게이트)는 이 단계가 없다. 녹화를 멈추면 곧장 작성 화면으로 넘어가고, 최대 60초짜리 원본이 그대로 첨부된다. 같은 제품 안에서 "영상을 다듬는다"는 경험이 캡처 방식에 따라 갈리고, 정작 길이가 긴 쪽(리플레이 30초 < 녹화 60초)에 다듬기가 없다.

리포트를 받는 사람 입장에서도 손해다. 60초 영상에서 버그가 나는 3초를 찾아야 하고, 그 60초 동안 쌓인 로그가 전부 붙어 온다. 트림은 **로그 신호 대 잡음비**를 올린다.

기술적으로 막혀 있던 것도 아니다. 자르기 화면(`ReplayTrimDialog`)·로그 트림(`trimByTime`)·타임라인 마커(`buildErrorMarkers`)는 이미 소스 중립이거나 벽시계 기준이라 그대로 쓸 수 있다. 유일하게 리플레이 전용인 것은 "선택 구간만 남긴 영상을 실제로 만드는" 부분 하나다 — 리플레이는 `CapturedFrame[]`(JPEG 프레임 배열)을 들고 있어 선택 프레임만 다시 인코딩하면 되지만, 녹화는 `MediaRecorder` 블롭 하나뿐이라 그 경로가 없다.

### 감수하는 트레이드오프

- **모든 녹화에 확정 클릭 1단계가 추가된다.** 길이 무관 항상 자르기 화면을 띄우기로 했다 — "정지하면 항상 자르기 화면"이 배울 규칙 하나로 끝나고, 길이 임계로 갈리면 규칙이 둘이 된다. 자를 게 없으면 그대로 확정하면 되고, 그 경로는 재인코딩·로그 재트림 없이 **대기 0**이다.
- **결과 파일이 원본보다 커질 수 있다.** 재인코딩이므로 코덱·비트레이트가 새로 잡힌다. 원본 실측 비트레이트에 맞춰 적응적으로 잡아 증가폭을 억제하지만, 트림의 목표는 용량 절감이 아니라 **구간 집중**이다.

## 목표

- 탭 녹화·화면 녹화를 정지하면 리플레이와 **동일한 자르기 화면**이 자동으로 뜬다(길이 무관).
- 자르기 화면에서 확정하면 선택 구간만 남긴 영상이 만들어지고, console·network·action 로그도 **같은 구간으로 좁혀진다**. 로그 탭에서 흐리게 보였던 항목이 실제로 빠진다.
- 핸들을 건드리지 않고 확정하면 **재인코딩·로그 재트림이 일어나지 않고** 원본 블롭이 그대로 첨부된다.
- 자르기 결과가 원본 해상도·프레임레이트를 유지한다(다운스케일 없음).

### 제약

- 새 npm 의존성을 추가하지 않는다. 기존 WebCodecs 스택(`mp4-muxer`)만 쓴다.
- 설정의 "30초 리플레이" 토글과 독립적으로 동작한다 — 별개 기능이다.
- 권한·`manifest.config.ts`·`docs/privacy.*` 변경이 없다(이미 만든 영상의 로컬 재인코딩).

## 비목표 (Non-goals)

- **무손실 stream copy(remux)** — 화질 손실 0을 얻으려면 컨테이너 디먹싱(mp4box.js 등)이 필요하다. 새 의존성 + 컷 지점이 키프레임에 스냅되는 정밀도 저하 + webm 폴백 별도 경로를 감수해야 해 이번 스코프에서 제외한다.
- **구간 여러 개 잘라내기(다중 컷)** — 리플레이와 동일하게 in/out 핸들 한 쌍, 연속 구간 하나만.
- **작성 화면에서 나중에 다시 자르기** — 자동 진입 1회로 한정한다. 원본 블롭을 계속 들고 있어야 해 메모리·상태가 늘어난다. **재인코딩 실패 시에도 재시도 경로는 없다**(원본이 그대로 첨부된다).
- **인코딩 중 취소** — 진행률은 보여주되 중단은 제공하지 않는다. 실패·정체는 watchdog이 잡아 원본 유지로 떨어뜨린다.
- **자르기 on/off 설정 추가** — 녹화 기능의 일부로 항상 켜져 있다.
- **오디오 트랙** — 현재 녹화는 `audio: false`라 해당 없음.
- **자르기 화면의 탭 구성·타임라인·마커 구조 변경** — 4탭·undo/redo·흐림 미리보기는 리플레이와 동일하게 재사용한다. 새 UI를 만들지 않는다. (예외로 이번에 손대는 것: 인코딩 진행률 표시, 오버레이 ARIA 속성, 취소·실패 문구 — 아래 참조)
- **60초 스케일에 맞춘 자르기 화면 개선** — 트랙 실폭 ~284px에서 60초는 1px≈2스텝(도달 불가 값 발생)이고, 마커 핀 하나가 3.4초를 덮는데 충돌 회피가 없어 겹친 핀은 클릭할 수 없다. 구간 readout(`"{sel}s / {total}s"`)도 남긴 길이만 알려주고 그게 60초 중 어디인지는 안 알려준다. 리플레이 UI와 갈라놓지 않기 위해 **전부 수용된 한계**로 둔다 — 60초 사용 실측 후 별도 작업으로 다룬다.
- **슬라이더 최소 구간 강제** — `step=0.1` + `minStepsBetweenThumbs=1`로 0.1초 구간까지 선택 가능한 기존 동작을 유지한다. 프레임 0개면 인코딩이 실패하고 원본 유지 경로로 떨어진다.
- **미리보기 재생 범위를 선택 구간으로 제한** — 리플레이와 동일하게 전체를 재생한다.

## 사용자 시나리오

### 주 플로우 — 탭 녹화 후 자르기

1. 디버그 화면에서 **녹화** 버튼을 눌러 탭 녹화를 시작한다.
2. 버그를 재현하고 **정지**를 누른다. (또는 60초 상한에 도달해 자동 정지)
3. 사이드패널 전체를 덮는 **자르기 화면**이 뜬다. 진입 안내 토스트("양쪽 손잡이를 끌어 버그 구간만 남겨보세요.")가 **자르기 화면이 뜰 때마다** 1회 표시된다(세션당 1회가 아니다 — 현행 리플레이 동작 그대로).
4. 상단 4탭(영상 / 콘솔 / 네트워크 / 액션) 중 **영상** 탭에서 재생하며 버그 지점을 찾는다. 타임라인에는 콘솔·네트워크 오류와 페이지 이동 마커가 표시된다.
5. 타임라인 양 끝 핸들을 끌어 남길 구간을 정한다. 로그 탭으로 넘어가면 **잘려나갈 로그가 흐리게** 표시된다.
6. **확정**을 누른다. 탭·타임라인이 비활성화되고 **진행률 바**와 "탭을 유지해 주세요" 안내가 뜬다.
7. 선택 구간만 남긴 영상이 만들어지고 로그가 좁혀진 뒤, 자르기 화면이 닫히며 **작성 화면**으로 넘어간다. 영상 프리뷰·재현 단계 자동 채움은 평소대로 동작한다.

### 자르지 않고 넘어가기

3~5단계에서 핸들을 건드리지 않고 바로 **확정**을 누른다 → **재인코딩·로그 재트림 없이 즉시** 작성 화면으로 넘어간다. 첨부되는 영상은 녹화 원본 그대로다.

### 취소

자르기 화면에서 **취소**(✕) → 확인 다이얼로그 → 확정하면 **녹화 전체를 폐기**하고 캡처 진입 화면으로 돌아간다. 저장 중이던 pending 로그·영상·첨부도 함께 정리된다. (리플레이 취소와 동일한 동작)

확인 다이얼로그 문구는 이 화면 전용으로 새로 만든다. 현재 공유 중인 `editor.cancelConfirm.*`("작성을 취소할까요? / 작성 중인 내용이 모두 초기화됩니다")는 **이 시점에 작성한 내용이 없고 실제로 잃는 건 방금 찍은 녹화**라 사실과 어긋난다.

### 화면 녹화

탭 녹화와 동일하다. 화면 녹화는 최대 1920×1080이므로 자르기 결과도 **그 해상도를 유지**한다(다운스케일하지 않는다).

### 엣지 케이스

- **아주 짧은 녹화(2~3초)** — 길이와 무관하게 자르기 화면을 띄운다. 자를 게 없으면 그대로 확정하면 되고, 그 경로는 재인코딩 없이 즉시 끝난다.
- **`<video>`가 duration을 못 읽거나 메타데이터 로드 자체가 실패** — 녹화 소스의 타임라인은 **처음부터 벽시계 길이(`videoEndedAt − videoStartedAt`)를 쓴다**. `<video>.duration`(MediaRecorder webm 블롭이면 `Infinity`)에 의존하지 않으므로 `loadedmetadata`가 아예 오지 않아도 타임라인이 그려지고 확정 버튼이 살아 있다. 미리보기 재생만 안 될 뿐 자르기·건너뛰기·취소 모두 가능하다.
- **정지 화면이 긴 녹화** — `MediaRecorder`는 damage 기반 가변 프레임레이트(12fps는 상한)라 미디어 길이가 벽시계 경과보다 크게 짧을 수 있다. 로그 경계·타임라인 축은 벽시계 기준이므로 영향받지 않는다. 미디어 길이가 유효하면 재생 헤드 위치만 비율로 환산한다.
- **인코딩 중 다른 탭으로 전환** — 사이드패널이 hidden이면 `requestVideoFrameCallback`이 **완전히 멈춘다**(프레임이 성겨지는 게 아니다). 진행률 바와 "탭을 유지해 주세요" 안내로 이탈을 억제하고, hidden 동안은 정체 watchdog을 멈춰 복귀 시 이어간다. 그래도 실패하면 원본 유지 경로로 떨어진다.
- **인코딩 중 사이드패널 문서가 사라짐**(탭 이동으로 패널 destroy) — `replayTrim`은 비영속이라 복귀 시 오버레이가 사라지고 원본이 붙은 작성 화면에 착지한다. **수용된 한계**로 둔다(트림 페이로드를 영속화하려면 Blob을 IDB에 들고 정리 경로를 늘려야 한다).
- **자르기 화면이 떠 있는 상태로 브라우저 탭 전환** — 오버레이는 원래 탭의 영상을 든 채 남는데 `tabId`만 새 탭으로 바뀌어, 그대로 확정하면 **엉뚱한 탭의 로그를 자른다**. 트림 페이로드에 소유 탭을 실어 불일치하면 확정을 막는다.
- **녹화 도중 탭이 닫힘** — `onstop`의 빈 viewport·target 폴백 경로를 탄다. 다만 탭이 닫히면 패널 문서도 통상 소멸하고 세션 키·pending 블롭이 정리되므로, **자르기 화면까지 도달하지 못하는 것이 정상 동작**이다. (기존 서술 정정)
- **사용자가 OS "공유 중지"로 화면 녹화를 끝냄** — `track ended` → `stopRecording()` → 동일 경로.
- **60초 상한 자동 정지** — 동일 경로. 사용자가 다른 사이드패널 탭(연동·설정·이슈 목록)을 보고 있어도 오버레이가 전면에 뜬다.
- **재인코딩 실패**(WebCodecs 미지원 코덱·디코딩 실패·재생 정체·프레임 0개) — 실패 토스트를 띄우고 **원본 영상을 유지한 채** 작성 화면으로 넘어간다. 녹화를 잃지 않는다. 토스트 문구는 재시도를 안내하지 않고 "원본이 그대로 첨부된다"를 알린다.
- **녹화 중 창 리사이즈·모니터 전환으로 해상도가 바뀐 소스** — 인코더는 첫 프레임 크기로 한 번만 구성되므로, 중간에 크기가 달라지면 그 프레임을 구성 크기로 맞춰 인코딩한다.
- **트림 후 액션 로그가 0건이 되는 구간** — 재현 단계 자동 채움은 액션 로그가 1건 이상일 때만 발화한다. 좁게 자르면 채워지지 않는 것이 정상 동작이다.

## 성공 기준

- 탭 녹화·화면 녹화 정지 후 자르기 화면이 자동으로 뜬다(길이 무관, 30초 리플레이 토글 OFF 포함).
- 핸들을 움직여 확정하면 결과 영상 길이가 선택 구간과 일치하고(±1프레임), 첨부 로그가 그 구간 밖 항목을 포함하지 않는다.
- 로그 탭에서 흐리게 표시됐던 항목이 확정 후 실제로 빠진다("흐림 = 실제 잘림" parity).
- 핸들을 안 건드리고 확정하면 재인코딩이 발생하지 않는다 — 결과 블롭이 원본과 동일 참조이고 `videoTrimmed === false`.
- 자른 영상의 해상도·프레임레이트가 원본과 같다. (화질은 별도 비차단 항목: 적응 비트레이트 적용 후 육안 저하가 없는지 수동 확인)
- `<video>.duration`이 `Infinity`이거나 `loadedmetadata`가 발화하지 않아도 타임라인이 그려지고 확정이 가능하다.
- 확정 후 **구간 내 액션 로그가 1건 이상이면** 재현 단계 자동 채움이 발화한다(POSTMORTEM 2026-07-17 회귀 없음). 0건이면 미발화가 정상.
- 자르기 화면 진입 시 흰 화면이 발생하지 않는다(POSTMORTEM 2026-07-01 회귀 없음).
- 인코딩 중 진행률이 갱신되고, 다른 탭에 다녀와도 정체 watchdog에 걸리지 않는다.
- `pnpm test`·`pnpm typecheck` 통과.
