# 녹화 구간 자르기 (Recording Trim)

## 배경

30s Replay로 캡처한 영상은 확정 전에 **자르기 화면**을 거친다 — 앞뒤 불필요한 구간을 잘라내고 버그 순간만 남기며, 함께 첨부되는 console·network·action 로그도 그 구간으로 좁혀진다.

반면 **탭 녹화·화면 녹화**(일반 record 게이트)는 이 단계가 없다. 녹화를 멈추면 곧장 작성 화면으로 넘어가고, 최대 60초짜리 원본이 그대로 첨부된다. 같은 제품 안에서 "영상을 다듬는다"는 경험이 캡처 방식에 따라 갈리고, 정작 길이가 긴 쪽(리플레이 30초 < 녹화 60초)에 다듬기가 없다.

리포트를 받는 사람 입장에서도 손해다. 60초 영상에서 버그가 나는 3초를 찾아야 하고, 그 60초 동안 쌓인 로그가 전부 붙어 온다. 트림은 영상 용량만이 아니라 **로그 신호 대 잡음비**를 함께 올린다.

기술적으로 막혀 있던 것도 아니다. 자르기 화면(`ReplayTrimDialog`)·로그 트림(`trimByTime`)·타임라인 마커(`buildErrorMarkers`)는 이미 소스 중립이거나 벽시계 기준이라 그대로 쓸 수 있다. 유일하게 리플레이 전용인 것은 "선택 구간만 남긴 영상을 실제로 만드는" 부분 하나다 — 리플레이는 `CapturedFrame[]`(JPEG 프레임 배열)을 들고 있어 선택 프레임만 다시 인코딩하면 되지만, 녹화는 `MediaRecorder` 블롭 하나뿐이라 그 경로가 없다.

## 목표

1. 탭 녹화·화면 녹화를 정지하면, 리플레이와 **동일한 자르기 화면**이 자동으로 뜬다.
2. 자르기 화면에서 확정하면 선택 구간만 남긴 영상이 만들어지고, console·network·action 로그도 **같은 구간으로 좁혀진다**.
3. 핸들을 건드리지 않고 그대로 확정하면 **재인코딩이 일어나지 않는다** — 원본 블롭이 그대로 첨부되고 `videoTrimmed`는 `false`로 남는다.
4. 자르기로 인한 화질 저하가 눈에 띄지 않는다 — 원본 해상도·프레임레이트를 유지하고, 2세대 인코딩 비트레이트를 원본보다 높게 잡는다.
5. 새 npm 의존성을 추가하지 않는다.
6. 설정의 "30초 리플레이" 토글이 꺼져 있어도 녹화 자르기는 동작한다 — 별개 기능이다.

## 비목표 (Non-goals)

- **무손실 stream copy(remux)** — 화질 손실 0을 얻으려면 컨테이너 디먹싱(mp4box.js 등)이 필요하다. 새 의존성 + 컷 지점이 키프레임에 스냅되는 정밀도 저하 + webm 폴백 별도 경로를 감수해야 해 이번 스코프에서 제외한다.
- **구간 여러 개 잘라내기(다중 컷)** — 리플레이와 동일하게 in/out 핸들 한 쌍, 연속 구간 하나만.
- **작성 화면에서 나중에 다시 자르기** — 자동 진입 1회로 한정한다. 원본 블롭을 계속 들고 있어야 해 메모리·상태가 늘어난다.
- **자르기 on/off 설정 추가** — 녹화 기능의 일부로 항상 켜져 있다.
- **오디오 트랙** — 현재 녹화는 `audio: false`라 해당 없음.
- **자르기 화면 UI 변경** — 탭 구성·타임라인·undo/redo·마커·흐림 미리보기는 리플레이와 완전히 동일하게 재사용한다. 새 UI를 만들지 않는다.

## 사용자 시나리오

### 주 플로우 — 탭 녹화 후 자르기

1. 디버그 화면에서 **녹화** 버튼을 눌러 탭 녹화를 시작한다.
2. 버그를 재현하고 **정지**를 누른다. (또는 60초 상한에 도달해 자동 정지)
3. 사이드패널 전체를 덮는 **자르기 화면**이 뜬다. 진입 안내 토스트("양쪽 손잡이를 끌어 버그 구간만 남겨보세요.")가 1회 표시된다.
4. 상단 4탭(영상 / 콘솔 / 네트워크 / 액션) 중 **영상** 탭에서 재생하며 버그 지점을 찾는다. 타임라인에는 콘솔·네트워크 오류와 페이지 이동 마커가 표시된다.
5. 타임라인 양 끝 핸들을 끌어 남길 구간을 정한다. 로그 탭으로 넘어가면 **잘려나갈 로그가 흐리게** 표시된다.
6. **확정**을 누른다. 확정 버튼이 스피너로 바뀌고 탭·타임라인이 비활성화된다.
7. 선택 구간만 남긴 영상이 만들어지고 로그가 좁혀진 뒤, 자르기 화면이 닫히며 **작성 화면**으로 넘어간다. 영상 프리뷰·재현 단계 자동 채움은 평소대로 동작한다.

### 자르지 않고 넘어가기

3~5단계에서 핸들을 건드리지 않고 바로 **확정**을 누른다 → **재인코딩·로그 재트림 없이 즉시** 작성 화면으로 넘어간다. 첨부되는 영상은 녹화 원본 그대로다.

### 취소

자르기 화면에서 **취소**(✕) → 확인 다이얼로그 → 확정하면 **녹화 전체를 폐기**하고 캡처 진입 화면으로 돌아간다. 저장 중이던 pending 로그·영상·첨부도 함께 정리된다. (리플레이 취소와 동일한 동작)

### 화면 녹화

탭 녹화와 동일하다. 화면 녹화는 최대 1920×1080이므로 자르기 결과도 **그 해상도를 유지**한다(다운스케일하지 않는다).

### 엣지 케이스

- **아주 짧은 녹화(2~3초)** — 길이와 무관하게 자르기 화면을 띄운다. 자를 게 없으면 그대로 확정하면 되고, 그 경로는 재인코딩 없이 즉시 끝난다.
- **녹화 도중 탭이 닫힘** — 기존 `onstop` 경로(빈 viewport·target 폴백)를 그대로 타고, 그 뒤 자르기 화면이 뜬다.
- **사용자가 OS "공유 중지"로 화면 녹화를 끝냄** — `track ended` → `stopRecording()` → 동일 경로.
- **60초 상한 자동 정지** — 동일 경로.
- **재인코딩 실패**(WebCodecs 미지원 코덱·디코딩 실패·재생 정체) — 실패 토스트를 띄우고 **원본 영상을 유지한 채** 작성 화면으로 넘어간다. 녹화를 잃지 않는다.
- **`<video>`가 duration을 못 읽는 경우**(MediaRecorder webm 블롭은 `duration === Infinity`) — 벽시계 기준 길이(`videoEndedAt − videoStartedAt`)로 폴백해 타임라인이 죽지 않게 한다.

## 성공 기준

- 탭 녹화·화면 녹화 정지 후 자르기 화면이 자동으로 뜬다(길이 무관).
- 핸들을 움직여 확정하면 결과 영상 길이가 선택 구간과 일치하고(±1프레임), 첨부 로그가 그 구간 밖 항목을 포함하지 않는다.
- 로그 탭에서 흐리게 표시됐던 항목이 확정 후 실제로 빠진다("흐림 = 실제 잘림" parity).
- 핸들을 안 건드리고 확정하면 재인코딩이 발생하지 않는다 — 결과 블롭이 원본과 동일 참조이고 `videoTrimmed === false`.
- 자른 영상의 해상도·프레임레이트가 원본과 같고, 육안으로 화질 저하가 확인되지 않는다.
- 설정에서 30초 리플레이 토글이 **꺼진** 상태에서도 위 전부가 동작한다.
- 자르기 화면 확정·취소 후 재현 단계 자동 채움이 정상 발화한다(POSTMORTEM 2026-07-17 회귀 없음).
- 자르기 화면 진입 시 흰 화면이 발생하지 않는다(POSTMORTEM 2026-07-01 회귀 없음).
- `pnpm test`·`pnpm typecheck` 통과.
