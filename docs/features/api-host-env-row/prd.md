# 재현 환경에 API 호스트 표시

## 배경

사내에서 BugShot으로 발행한 지라 티켓에서 QA와 BE가 코멘트 3왕복을 했다.

> QA "어느 URL에서 확인하냐" → BE가 브랜치 API 호스트(`epic-comm-per-third.api.qa.skillflo.io`)
> 안내 → QA "프론트도 API를 맞춰야 하는군요"

재현 환경 표에 API 호스트 칸이 없어서 생긴 순수 낭비다. 지금 본문에 있는 건 웹 URL(`Page` 행)
뿐이고, 실제 요청이 어느 호스트로 갔는지는 첨부된 `logs.html`을 열어야 알 수 있다. 그 정보는
**이미 캡처된 네트워크 로그의 full URL에 들어 있다** — 새 수집 없이 파생만 하면 된다.

브랜치별 API 호스트를 쓰는 팀(QA/스테이징 환경이 PR마다 갈리는 조직)에서 이 왕복은 티켓마다
반복된다.

## 목표

1. 로그가 첨부된 캡처의 이슈 본문·화면·`logs.html` 재현 환경에 **API 호스트 행이 자동으로
   채워진다**. 사용자가 아무것도 안 해도 된다.
2. 그 값이 **틀렸을 때 사용자가 고치거나 지울 수 있다**. 재현 환경에 틀린 호스트를 적으면
   이 기능이 없애려던 코멘트 왕복을 오히려 재현하기 때문이다.
3. 8개 플랫폼 제출 본문 · 마크다운 복사 · 사이드패널 작성/미리보기 화면 · 저장된 이슈 상세 ·
   `logs.html` Report 탭이 **같은 값을 보여준다**(화면↔본문 비대칭 없음).
4. 서드파티 호스트(Sentry·GA·Intercom·CDN)를 API 호스트로 오라벨하지 않는다.

## 비목표 (Non-goals)

- **API 호스트 자동 감지의 완전성.** 다중 백엔드·게이트웨이 분리 환경에서 모든 호스트를
  나열하지 않는다. 대표 1개만 채우고, 나머지는 사용자가 행을 더해 적는다.
- **요소 스타일 편집(element) 모드 지원.** 이 모드는 로그를 수집하지 않는 것이 문서화된
  약속이다(`guide/*/logs/README.md`). 로그 파생값도 나가지 않는다.
- **읽기 전용(readonly) 행으로의 편입.** OS·Browser·Page·DOM·Viewport·Captured와 달리
  이 값은 휴리스틱 추정이므로 사용자가 손댈 수 있어야 한다.
- **`IssueRecord` 스키마 확장.** 아래 설계에서 불필요해진다.
- **네트워크 로그 수집 범위 변경.** 현재 fetch/XHR 후크 그대로 쓴다.

## 사용자 시나리오

### 주 시나리오 — 스크린샷 캡처 후 이슈 등록

1. 사용자가 QA 환경(`https://app-epic-comm.qa.skillflo.io/orders/42`)에서 버그를 만나 영역
   스크린샷을 찍는다. 로그는 기본 첨부(on)다.
2. 작성 화면으로 넘어오면 재현 환경 섹션에 행이 하나 자동으로 들어와 있다:
   `API Host | https://epic-comm-per-third.api.qa.skillflo.io`
3. 사용자는 그대로 두고 이슈를 등록한다. 지라 본문 재현 환경 목록에 그 줄이 찍힌다.
4. BE가 티켓만 보고 어느 API를 볼지 안다. 코멘트 왕복 0회.

### 부 시나리오 — 값이 마음에 안 들 때

2번 상태에서 사용자가 값 입력칸을 클릭해 직접 고치거나, 행 삭제 버튼으로 지운다. 지운 상태로
등록하면 본문에도 안 나간다.

### 엣지 케이스

| 상황 | 동작 |
|---|---|
| 페이지가 자기 origin으로만 요청(BFF·SSR 프록시) | 행 없음 — `Page`와 중복 정보라 가치 0 |
| 동족 API origin이 2개 이상(`api.` + `auth.`) | 요청 수가 가장 많은 origin 1개. 동률이면 먼저 나온 쪽 |
| Sentry·GA만 실패, 자사 API는 정상 | 행 없음 — 동족 도메인이 아니다 |
| 로그 첨부를 껐다(`logsAttach` off) | 행 없음 |
| element 모드 | 행 없음 (모드 게이트) |
| 네트워크 요청 0건 | 행 없음 |
| 사용자가 지운 뒤 계속 작업 | 되살아나지 않음 (draft 생성 시 1회만 주입) |

## 성공 기준

- 로그가 첨부된 screenshot/video/freeform 캡처에서, 페이지와 다른 동족 origin으로 XHR이
  1건 이상 나간 경우 작성 화면 재현 환경에 `API Host` 행이 보인다.
- 그 행이 8개 플랫폼 제출 본문 · 마크다운 복사 · 미리보기 · 저장 이슈 상세 · `logs.html`
  Report 탭 전부에 동일하게 나타난다.
- element 모드에서는 어떤 순서로 진입해도 행이 생기지 않는다(스크린샷 캡처 → element 픽
  순서 포함 — `preserveLogs`가 로그를 보존하는 경로).
- 행의 값 수정·삭제가 즉시 본문에 반영된다.
- `pnpm test` 통과. 기존 골든 스냅샷 62개 무변경.
