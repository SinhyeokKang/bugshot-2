# 재현 환경에 API 호스트 표시

## 배경

사내에서 BugShot으로 발행한 지라 티켓에서 QA와 BE가 코멘트 3왕복을 했다.

> QA "어느 URL에서 확인하냐" → BE가 브랜치 API 호스트(`epic-comm-per-third.api.qa.skillflo.io`)
> 안내 → QA "프론트도 API를 맞춰야 하는군요"

재현 환경 표에 API 호스트 칸이 없어서 생긴 순수 낭비다. 지금 본문에 있는 건 웹 URL(`Page` 행)
뿐이고, 실제 요청이 어느 호스트로 갔는지는 첨부된 `logs.html`을 열어야 알 수 있다. 그 정보는
**이미 캡처된 네트워크 로그의 full URL에 들어 있다** — 새 수집 없이 파생만 하면 된다.

### 왜 본문 로그 요약으로는 안 되는가

"로그에 이미 있는데 대표 호스트 하나를 Env에 넣는 게 의미가 있나"는 당연한 반문이고, 답은
**본문이 호스트를 한 번도 인쇄하지 않는다**는 코드 사실이다:

- `buildNetworkLogSummary`가 `extractPath()`(`buildLogSummary.ts:114`)로 **pathname만** 남기고
  origin을 버린다.
- 그 요약이 나열하는 건 `status >= 400 || phase === "error"`인 요청뿐이고, dedup 후 최대 5건이다.

그래서 실사례처럼 **정상 동작 중 캡처한 리포트**에서는 본문 로그 요약이 `네트워크 12건` 같은
건수 한 줄로 끝난다. 호스트에 닿는 경로는 둘뿐이고 둘 다 비싸다: ① `logs.html`을 내려받아 열고
네트워크 탭을 스캔 — 읽는 사람이 이미 "API가 의심된다"고 짐작해야 시작하는 행동이다 ② 작성자가
로그 1건을 골라 본문에 인라인 삽입 — 수동·1건씩이고, **어느 요청이 중요한지 작성자가 이미
알아야** 쓸 수 있다.

즉 실패의 정체는 "정보가 없다"가 아니라 **"첨부를 열 이유를 아는 사람만 도달할 수 있다"**다.
코멘트 3왕복이 `logs.html`이 이미 첨부된 상태에서 일어난 것이 그 증거고, Env 행은 그 도달
비용을 0으로 만든다. 대표 1개라는 한계는 남지만, 실사례 값처럼 **브랜치 식별자가 호스트에
박히는 팀**에서는 1개로 충분하다 — 다중 백엔드에서 최다 origin이 임의적인 건 비목표로 닫았다.

브랜치별 API 호스트를 쓰는 팀(QA/스테이징 환경이 PR마다 갈리는 조직)에서 이 왕복은 티켓마다
반복된다.

## 목표

1. 로그가 첨부된 캡처의 이슈 본문·화면·`logs.html` 재현 환경에 **API 호스트 행이 자동으로
   채워진다**. 사용자가 아무것도 안 해도 된다.
2. 그 값이 **틀렸을 때 사용자가 고치거나 지울 수 있다**. 재현 환경에 틀린 호스트를 적으면
   이 기능이 없애려던 코멘트 왕복을 오히려 재현하기 때문이다. 값이 주입됐다는 사실이
   **사용자에게 보여야** 이 목표가 성립한다 — 존재를 모르는 값은 고칠 수 없다.
3. 8개 플랫폼 제출 본문 · 마크다운 복사 · 사이드패널 작성/미리보기 화면 · 저장된 이슈 상세 ·
   `logs.html` Report 탭이 **같은 값을 보여준다**(화면↔본문 비대칭 없음).
4. 서드파티 호스트(Sentry·GA·Intercom·CDN)를 API 호스트로 오라벨하지 않는다.

### 프라이버시 정합 (코어밸류 축)

새 수집·새 전송 경로를 만들지 않는다 — **이미 수집된 네트워크 로그에서 파생만 한다.** 다만
파생값이 **첨부 파일이 아니라 이슈 본문 평문**으로 나가므로, 노출 면적은 늘어난다:

- `logs.html`이 용량 캡으로 빠진 리포트(`logsDropped`)에도 본문 줄은 남는다.
- Slack 공유는 채널 메시지 본문이라, 첨부를 열지 않는 멤버에게도 내부 QA/스테이징 호스트명이
  보인다.

따라서 `docs/privacy.{ko,en}.md` 대조·갱신은 이 기능의 **완료 조건**이다(성공 기준 참조).
manifest diff가 0이어도 예외가 아니다 — 30s Replay가 같은 검사를 빠져나가 웹스토어 심사에
탈락한 전례가 있다(`docs/POSTMORTEM.md`).

## 비목표 (Non-goals)

- **API 호스트 자동 감지의 완전성.** 다중 백엔드·게이트웨이 분리 환경에서 모든 호스트를
  나열하지 않는다. 대표 1개만 채우고, 나머지는 사용자가 행을 더해 적는다.
- **요소 스타일 편집(element) 모드 지원.** 이 모드는 로그를 수집하지 않는 것이 문서화된
  약속이다(`guide/*/logs/README.md`). 로그 파생값도 나가지 않는다.
- **읽기 전용(readonly) 행으로의 편입.** OS·Browser·Page·DOM·Viewport·Captured와 달리
  이 값은 휴리스틱 추정이므로 사용자가 손댈 수 있어야 한다.
- **`IssueRecord` 스키마 확장.** `design.md` 대안 검토 A에서 불필요해진다.
- **네트워크 로그 수집 범위 변경.** 현재 fetch/XHR 후크 그대로 쓴다.
- **설정 탭의 자동 채움 on/off 토글.** 매번 지우는 사용자가 요구할 표면이지만, 행 삭제가
  1클릭이므로 설정 항목을 하나 늘릴 값이 안 된다. 요구가 반복 관측되면 별도 `/feature`.
- **`TWO_LEVEL_SUFFIXES` 목록의 증분 확장.** "우리 회사 도메인도 넣어달라" 요구를 받지 않는다.
  대표 1개 + 요청 수 tie-break는 곧 가중치 튜닝 요구로 번지는 표면이고, 오판정의 대가가
  "행이 하나 잘못 뜨거나 안 뜬다"라 사용자 수정으로 흡수된다.
- **라벨 i18n.** 하드코딩 영문 `API Host`로 둔다(기존 env 라벨 6종과 동일 — `design.md`
  "기존 패턴 준수").
- **효과 측정용 analytics 차원 추가.** `api_host_row: kept|edited|removed` 같은 집계는 넣지
  않는다. 측정하려면 별도 결정으로 다룬다.
- **AI 초안 프롬프트에 API 호스트 컨텍스트 주입.** 이 기능은 재현 환경 표시까지다.

## 사용자 시나리오

### 주 시나리오 — 스크린샷 캡처 후 이슈 등록

1. 사용자가 QA 환경(`https://app-epic-comm.qa.skillflo.io/orders/42`)에서 버그를 만나 영역
   스크린샷을 찍는다. 로그는 기본 첨부(on)다.
2. 작성 화면으로 넘어오면 재현 환경 섹션이 **펼쳐진 상태로** 열리고 행이 하나 들어와 있다:
   `API Host | https://epic-comm-per-third.api.qa.skillflo.io`
   (기본은 접힌 섹션이다 — 자동 주입 행이 있을 때만 펼쳐진다. 목표 2의 전제.)
3. 사용자는 그대로 두고 이슈를 등록한다. 지라 본문 재현 환경 목록에 그 줄이 찍힌다.
4. BE가 티켓만 보고 어느 API를 볼지 안다. 코멘트 왕복 0회.

### 부 시나리오 — 값이 마음에 안 들 때

2번 상태에서 사용자가 값 입력칸을 클릭해 직접 고치거나, 행 삭제 버튼으로 지운다. 지운 상태로
등록하면 본문에도 안 나간다. 입력칸이 좁아 긴 origin의 꼬리가 잘리므로, hover 시 전문이
툴팁으로 보인다.

### 엣지 케이스

| 상황 | 동작 |
|---|---|
| 페이지가 자기 origin으로만 요청(BFF·SSR 프록시) | 행 없음 — `Page`와 중복 정보라 가치 0 |
| 동족 API origin이 2개 이상(`api.` + `auth.`) | 요청 수 최다 1개 (규칙은 design.md) |
| Sentry·GA만 실패, 자사 API는 정상 | 행 없음 — 동족 도메인이 아니다 |
| WebSocket(`wss://`)만 동족 | 행 없음 — http/https만 후보 |
| 캡처 시 로그 첨부 off | 행 없음 |
| **캡처 후 작성 화면에서 로그 첨부를 off로 토글** | **행 유지** — 주입은 draft 생성 시 1회뿐. 지우려면 행 삭제 버튼 |
| **캡처 시 off였다가 작성 화면에서 on으로 토글** | **행 없음** — 되메우지 않음 |
| element 모드 | 행 없음 (모드 게이트) |
| 네트워크 요청 0건 | 행 없음 |
| 사용자가 지운 뒤 계속 작업 | 되살아나지 않음 (draft 생성 시 1회만 주입) |
| 캡처 중 페이지 이동으로 직전 페이지 요청이 로그에 섞임 | 그 요청도 집계에 들어가 대표 origin이 뒤집힐 수 있음 — 수용 (design.md 위험 3) |
| 로그가 draft 생성보다 늦게 도착 | 행 없음 — 되메우지 않음. freeform이 이 레이스에 가장 취약 |

## 성공 기준

- 로그가 첨부된 screenshot/video/freeform 캡처에서, 페이지와 다른 동족 origin으로 http(s)
  요청이 1건 이상 나간 경우 작성 화면 재현 환경 섹션이 **펼쳐진 채** `API Host` 행을 보여준다.
- 그 행이 8개 플랫폼 제출 본문 · 마크다운 복사 · 미리보기 · 저장 이슈 상세 · `logs.html`
  Report 탭 전부에 동일하게 나타난다.
- **상용 플랫폼(지라 또는 GitHub)에 실제 이슈를 제출해 본문 재현 환경 목록에 `API Host` 줄이
  있는 것을 눈으로 확인했다.** 이전 시도가 화면만 보고 통과시켜 "화면엔 있고 본문엔 없는"
  비대칭을 만들고 롤백된 유일한 하드 실패 이력이라, 화면 검증으로 대체하지 않는다.
- element 모드에서는 어떤 순서로 진입해도 행이 생기지 않는다(로그를 보존하는 취소 경로
  `cancelRecording`·`cancelPicking` 경유 포함 — `preserveLogs` 경로).
- 행의 값 수정·삭제가 즉시 본문에 반영된다.
- `docs/privacy.{ko,en}.md`가 "본문 평문에 실린다"는 사실을 ko/en 동시에 반영했다.
- `pnpm test` 통과. 기존 골든 스냅샷 62개 무변경.
