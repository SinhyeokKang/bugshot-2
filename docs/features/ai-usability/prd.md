# AI 에이전트 사용성 (ai-usability)

## 배경

1.7.55 스토어판을 ego-browser 에이전트로 런타임 스모크(2026-10-15)하며, 에이전트가 BugShot을 직접 써서 이슈를 캡처·제출하는 경로의 마찰을 수집했다. 제출 자체는 7개 목적지 전부 성공했지만, 거기까지 가는 데 사람이라면 겪지 않는 함정이 여럿 있었다.

- **패널을 에이전트가 열 수 없다.** `sidePanel.open`은 사용자 클릭을 요구한다. 그래서 에이전트는 `chrome-extension://<ID>/src/sidepanel/index.html?tabId=N`을 **일반 탭으로** 연다(이하 "탭 모드"). e2e `openPanel`도 같은 방식이다.
- **탭 모드에서는 캡처가 조용히 실패한다.** 패널 탭을 조작하면 같은 창의 대상 탭이 비활성이 된다. 그러면 `captureOwnedTab`(`background/capture-throttle.ts:79`)이 `no longer the active tab`으로 거부하고, 패널은 `console.error`만 찍고 `null`을 받는다(`sidepanel/capture.ts:107`). UI에는 "No snapshot"만 남는다. 사람이 패널 URL을 탭으로 열어도 똑같다.
- **같은 창에서 탭을 바꾸면 로그 레코더가 멈춘다.** `tabs.onActivated` → `stopRecorders(prevTabId)`(`background/tab-bindings.ts:319`) 때문이다.
  - 그래서 기존 에이전트 매뉴얼(`src/sidepanel/index.html` `#__BUGSHOT_AGENT__`)은 "패널을 별도 창으로"를 정답으로 둔다.
  - 그런데 ego처럼 **창 하나에 묶인 에이전트**는 별도 창을 쓸 수 없다. 탭을 새 창으로 옮기자 태스크 스페이스에서 빠져 조작이 끊겼다.
- **매뉴얼을 발견할 수 없다.** 매뉴얼은 `<head>`의 inert script라 접근성 스냅샷(에이전트의 주 관측 수단)에 나오지 않는다. 이번 스모크도 매뉴얼을 모른 채 진행해 위 함정을 하나씩 다시 밟았다.
- **`?tabId=` 없이 탭으로 열면 자기 자신에 묶인다.** `useBoundTabId`의 폴백이 "마지막 포커스 창의 활성 탭" = 패널 탭 자신이다. 그 결과 "지원하지 않는 페이지" 안내가 뜬다.
  - tabId는 확장 페이지에서 `chrome.tabs.query`를 평가해야만 얻을 수 있어서, 에이전트의 진입 장벽이 된다.
- **아이콘 전용 탭에 접근성 이름이 없다.** 제출 모달 플랫폼 탭(`SubmitPlatformTabs`, `forceCollapsed`)에서 접힌 `TabLabel`이 `hidden`(display:none)이다(`components/ui/collapsing-tabs.tsx:77`).
  - 그래서 이름이 사라진다. 브랜드 아이콘은 svg title 덕에 이름이 남지만, Slack·Webhook은 비어 순서로 집어야 했다.

## 목표

1. **같은 창 탭 모드가 사이드패널과 동등하게 동작한다.** 탭 모드에서 패널 탭과 대상 탭을 오가도:
   - 대상 탭의 로그 레코더가 멈추지 않는다.
   - 패널에서 시작한 캡처(뷰포트·전체 페이지·요소 before/after·재캡처)가 대상 탭을 잠시 앞으로 가져와 성공한다.
2. **캡처 실패에 이유가 담긴 토스트가 뜬다.** 비활성 탭·rate limit·요소가 화면 밖/0 크기·기타로 분류한다. 지금 `console.error`만 남는 경로가 대상이다.
3. **`?tabId=` 없이 탭으로 열면 대상 탭 선택 화면이 뜬다.** 같은 창의 지원 탭 목록에서 고르면 그 탭에 바인딩된다.
4. **탭 모드에서만 에이전트 매뉴얼 안내가 화면(접근성 트리)에 노출된다.** 사이드패널(사람) UI는 바뀌지 않는다.
5. **아이콘 전용 탭에도 접근성 이름이 있다.** 접힌 라벨이 스크린리더·에이전트에게 읽힌다.
6. **사용자 가이드에 "AI 에이전트로 BugShot 쓰기" 페이지를 추가한다**(ko·en).

## 비목표 (Non-goals)

- **탭 녹화·화면 녹화 자동화.** `tabCapture.getMediaStreamId`는 activeTab 부여(툴바 클릭)를 요구해 에이전트가 원천적으로 못 쓴다("Extension has not been invoked"). 폴백 `getDisplayMedia` 선택 창은 브라우저 자체 UI다. 매뉴얼의 "Do not attempt video recording"을 유지한다.
- **30s 리플레이의 탭 모드 보정.** 폴링은 대상 탭이 활성일 때만 프레임을 쌓는다(`use-30s-replay.ts:74`). 탭 모드에서는 패널을 보는 동안 프레임이 빈다. 가이드·매뉴얼에 한계로만 적는다.
- **마크다운 `.md` 다운로드.** 결과 확인은 미리보기 DOM으로 충분하고, 주 경로는 제출이다.
- **Radix Tabs가 mousedown에만 반응하는 문제.** 표준 동작이다. 이번 스모크에서 문제가 된 건 ego의 제어권 오판 상태뿐이다.
- **별도 창 모드 제거.** 기존 "별도 창" 경로는 그대로 동작해야 한다. 같은 창은 추가 지원이다.
- 사이드패널(정상 모드)의 동작 변경. 실패 토스트(목표 2)와 접근성 이름(목표 5)만 양쪽 공통이다.

## 사용자 시나리오

### S1. 에이전트 — 같은 창 탭 모드로 스크린샷 이슈 제출
1. 에이전트가 대상 페이지 탭 T를 연다. 이어서 같은 창에 `chrome-extension://<ID>/src/sidepanel/index.html`을 연다(쿼리 없음).
2. 패널이 대상 탭 선택 화면을 보여 준다. 목록에 T가 있다. 에이전트가 T를 고르면 URL이 `?tabId=T`로 바뀌어 바인딩된다.
3. 화면 상단의 탭 모드 안내 한 줄("Automated agents: read #__BUGSHOT_AGENT__ in this page's source")이 접근성 스냅샷에 보인다. 에이전트가 매뉴얼을 읽는다.
4. 에이전트가 T로 가서 버그를 재현한다. T가 활성인 동안 레코더가 돈다.
5. 에이전트가 패널 탭으로 돌아온다. 이때 T의 레코더는 **멈추지 않는다**(패널 탭이 T에 바인딩된 자기 패널이므로).
6. `[mode-screenshot]` → `[capture-method-viewport]`를 누른다.
   - 패널이 T를 잠시 활성화해 캡처하고 다시 패널 탭을 활성화한다.
   - drafting으로 넘어가고, 로그 첨부 카드에 4단계의 로그가 있다.
7. 제목 입력 → 미리보기 → 제출.

### S2. 에이전트 — 요소 스타일 편집
1. S1의 1–3과 같다. 에이전트가 `[mode-element]`를 누르면 picking 진입과 동시에 패널이 T를 활성화한다.
2. 에이전트가 T에서 요소를 클릭한다. before가 찍히고 styling으로 넘어가면 패널 탭이 다시 활성화된다.
3. 값을 편집하고 Next를 누르면, after 캡처 동안 T가 잠시 활성화됐다가 돌아온다. before/after가 둘 다 있다.

### S3. 사람 — 패널 URL을 탭으로 연 경우
S1·S2와 같은 이점을 얻는다. 지금은 캡처가 "No snapshot"으로 조용히 실패하는 경로다.

### S4. 캡처 실패 토스트 (사이드패널·탭 모드 공통)
- 캡처가 큐에서 대기하는 동안 사용자가 다른 탭으로 전환함 → "대상 탭이 앞에 있어야 캡처할 수 있어요" 토스트 + 기존 복귀 동작(idle 리셋·after 없음 등) 유지.
- 요소가 뷰포트 밖이거나 0 크기여서 `captureWithPrep`가 null → "요소가 화면에 보이지 않아 캡처하지 못했어요".
- rate limit 재시도 3회 소진 → "캡처 요청이 몰렸어요. 잠시 후 다시 시도해 주세요".
- 그 외 → 일반 실패 문구. activeTab 만료는 기존 다이얼로그(`onPickerPermissionExpired`)가 그대로 처리하고 토스트를 겹치지 않는다.

### 엣지 케이스
- **탭 모드인데 대상 탭이 다른 창에 있음**(기존 별도 창 경로): 이미 양쪽 다 활성이라 handoff를 하지 않는다.
- **선택 화면에서 지원 탭이 하나도 없음**: "이 창에 캡처할 수 있는 페이지 탭이 없어요" 안내 + 새로고침 버튼.
- **패널 탭 → 제3의 탭 전환**: T의 레코더를 멈춘다. 기존 "세 번째 탭에서 일하면 기록이 멈춘다"는 계약을 유지한다.
- **handoff 중 대상 탭이 닫힘**: 캡처 실패 토스트(기타) + 패널 탭은 그대로 둔다.
- **사이드패널(정상 모드)**: `chrome.tabs.getCurrent()`가 `undefined`라 탭 모드 로직이 전부 비활성이다.

## 성공 기준

- 같은 창 탭 모드에서 S1·S2가 e2e로 통과한다. 이때 spec이 `fixture.bringToFront()` 우회 없이 패널 버튼만 누른다.
- 같은 창 탭 모드에서 패널 탭 ↔ 대상 탭을 오간 뒤에도 대상의 console/network/action 로그가 계속 쌓인다(e2e).
- 패널 탭 → 제3의 탭 전환 시 대상 레코더가 정지한다(단위 + e2e).
- 실패 4분류가 토스트로 뜬다. 분류 순수 함수는 단위 테스트로, 비활성 탭 경로 1개는 e2e로 확인한다.
- 접힌 플랫폼 탭이 `getByRole("tab", { name: "Custom Webhook" })`로 잡힌다(jsdom).
- `agentManual.test.ts` green. 매뉴얼의 같은 창 지원·대상 탭 선택·탭 모드 안내 주장이 소스에 바인딩돼 있다.
- 사이드패널 정상 모드에서 기존 e2e가 전부 green이다(회귀 0).
