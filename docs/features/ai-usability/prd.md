# AI 에이전트 사용성 (ai-usability)

## 가드레일

**사람 UI(사이드패널 정상 모드)는 가능한 한 바뀌지 않는다.** 이 스펙의 화면 변경은 전부 탭 모드(`chrome.tabs.getCurrent()`가 Tab을 돌려줄 때)에서만 렌더한다. 예외는 둘이고 둘 다 명시적으로 합의했다.

- **캡처 실패 토스트(목표 2)**: 사이드패널에서도 뜬다. 지금 무음으로 idle 리셋·"No snapshot"만 남는 실패를 사람에게도 알리는 게 이득이라 예외로 둔다.
- **접힌 탭 라벨(목표 5)**: 화면 변화는 0이다(`hidden` → `sr-only`). 스크린리더·접근성 트리에 이름만 생긴다.

새 결정이 이 가드레일과 부딪히면 탭 모드 게이트 뒤로 보내는 쪽을 먼저 검토한다.

## 배경

**주 사용자는 브라우저 에이전트다 — 내부와 외부 둘 다.** 내부는 우리 QA 자동화(ego-browser 런타임 스모크)이고, 외부는 고객이 자기 브라우저 에이전트(ego·Claude in Chrome 류)에게 "이 버그를 BugShot으로 리포트해"를 맡기는 경우다. 에이전트가 웹을 직접 조작하는 사용 형태가 늘고 있어서, 지금 에이전트가 BugShot을 쓰다 막히는 지점을 없애 두면 사람이 하던 리포팅 루프를 그대로 위임할 수 있다. 이 경로도 캡처 데이터는 **사용자 브라우저 → 사용자의 트래커로 직행**하므로 코어 밸류(Privacy, 클라이언트 온리)와 충돌하지 않는다. 기존 매뉴얼 범위를 "도그푸딩 리포팅 경로"로 한정한 `docs/ARCHITECTURE.md` 서술도 이 기능과 함께 넓힌다.

1.7.55 스토어판을 ego-browser 에이전트로 런타임 스모크(2026-10-15)하며, 에이전트가 BugShot을 직접 써서 이슈를 캡처·제출하는 경로의 마찰을 수집했다. 제출 자체는 테스트 대상 7개(GitHub·GitLab·Notion·Asana·ClickUp·Linear·Webhook — Jira·Slack은 실사용 공간이라 제외) 전부 성공했지만, 거기까지 가는 데 사람이라면 겪지 않는 함정이 여럿 있었다.

- **패널을 에이전트가 열 수 없다.** `sidePanel.open`은 사용자 클릭을 요구한다. 그래서 에이전트는 `chrome-extension://<ID>/src/sidepanel/index.html?tabId=N`을 **일반 탭으로** 연다(이하 "탭 모드"). e2e `openPanel`도 같은 방식이다.
- **탭 모드에서는 캡처가 조용히 실패한다.** 패널 탭을 조작하면 같은 창의 대상 탭이 비활성이 된다. 그러면 `captureOwnedTab`(`background/capture-throttle.ts:79`)이 `no longer the active tab`으로 거부한다. 실패는 사람 화면에도 드러나지 않는다:
  - 요소 before/after는 "No snapshot"만 남는다(`sidepanel/capture.ts:107`).
  - 뷰포트·영역·요소 캡처·전체 페이지는 조용히 idle로 리셋된다(`usePickerMessages.ts:402-442`, `IssueTab.tsx:120-173`).
  - diff 재캡처는 아무 반응이 없다(`StyleChangesDialog.tsx:98`).
  - 사람이 패널 URL을 탭으로 열어도 똑같다.
- **같은 창에서 대상 탭 ↔ 패널 탭을 오가면 레코더가 끊겼다 다시 붙는다.** `tabs.onActivated` → `stopRecorders(prevTabId)`(`background/tab-bindings.ts:319`)가 T를 멈추고, 패널 문서의 `visibilitychange`가 곧바로 재무장한다(`useBackgroundRecorder.ts:113-118`). 지금은 짧은 공백에 그치지만, 캡처 handoff(목표 1)를 넣으면 **캡처마다 stop → re-arm이 반복**된다. 정지 예외가 필요한 진짜 이유다.
  - 그래서 기존 에이전트 매뉴얼(`src/sidepanel/index.html` `#__BUGSHOT_AGENT__`)은 "패널을 별도 창으로"를 정답으로 둔다.
  - 그런데 ego처럼 **창 하나에 묶인 에이전트**는 별도 창을 쓸 수 없다. 탭을 새 창으로 옮기자 태스크 스페이스에서 빠져 조작이 끊겼다.
- **매뉴얼을 발견할 수 없다.** 매뉴얼은 `<head>`의 inert script라 접근성 스냅샷(에이전트의 주 관측 수단)에 나오지 않는다. 이번 스모크도 매뉴얼을 모른 채 진행해 위 함정을 하나씩 다시 밟았다.
- **`?tabId=` 없이 탭으로 열면 엉뚱한 탭에 묶인다.** `useBoundTabId`의 폴백이 "마지막 포커스 창의 활성 탭"이다. 패널 탭을 포그라운드로 열면 자기 자신(→ "지원하지 않는 페이지" 안내), 백그라운드로 열거나 다른 창이 포커스면 임의의 페이지 탭에 **무음으로** 묶인다.
  - tabId는 확장 페이지에서 `chrome.tabs.query`를 평가해야만 얻을 수 있어서, 에이전트의 진입 장벽이 된다.
- **아이콘 전용 탭에 접근성 이름이 없다.** 제출 모달 플랫폼 탭(`SubmitPlatformTabs`, `forceCollapsed`)에서 접힌 `TabLabel`이 `hidden`(display:none)이다(`components/ui/collapsing-tabs.tsx:77`).
  - 그래서 이름이 사라진다. 브랜드 아이콘은 svg title 덕에 이름이 남지만, Slack·Webhook은 비어 순서로 집어야 했다.

## 목표

1. **같은 창 탭 모드에서 캡처·로그 기록이 사이드패널과 동등하게 동작한다.** (리플레이·녹화는 비목표) 탭 모드에서 패널 탭과 대상 탭을 오가도:
   - 대상 탭 T ↔ T에 바인딩된 자기 패널 탭 사이 전환으로는 T의 레코더가 멈추지 않는다.
   - 패널에서 시작한 캡처(뷰포트·전체 페이지·요소 before/after·요소 캡처·재캡처·인라인 영역)가 대상 탭을 잠시 앞으로 가져와 성공하고, 끝나면 패널로 돌아온다.
   - 영역 드래그 캡처는 사용자가 직접 대상 탭으로 가서 드래그한다. 탭 모드에서만 그 안내를 한 줄 보인다.
2. **캡처 실패에 이유가 담긴 토스트가 뜬다**(가드레일 예외 — 사이드패널 공통). 분류는 비활성 탭·rate limit·요소를 찾지 못함·기타다. 사용자 취소·의도된 스킵·권한 만료(기존 다이얼로그)는 토스트를 띄우지 않는다.
3. **`?tabId=` 없이 탭으로 열면 대상 탭 선택 화면이 뜬다.** 모든 창의 지원 탭(같은 창 먼저)에서 고르면 그 탭에 바인딩된다.
4. **탭 모드에서만 에이전트 매뉴얼 안내가 화면(접근성 트리)에 노출된다.** 사이드패널(사람) UI는 바뀌지 않는다. 탭 모드로 쓰는 사람(S3)에게도 이 한 줄이 보이는 건 허용한다.
5. **아이콘 전용 탭에도 접근성 이름이 있다.** 접힌 라벨이 스크린리더·에이전트에게 읽힌다(화면 변화 0).
6. **사용자 가이드에 "AI 에이전트로 BugShot 쓰기" 최소 페이지를 추가한다**(ko·en). 사람 독자용으로 "에이전트에게 패널 URL을 주고 매뉴얼을 읽게 하라" + 한계만 다룬다. 조작 사실은 그물이 있는 매뉴얼 한 곳에 둔다.

목표 2·5는 탭 모드와 독립이라 tasks의 Phase A로 먼저 ship할 수 있다.

## 비목표 (Non-goals)

- **사이드패널(정상 모드)의 화면·동작 변경.** 가드레일 참조. 예외는 목표 2·5뿐이다.
- **탭 녹화·화면 녹화 자동화.** `tabCapture.getMediaStreamId`는 activeTab 부여(툴바 클릭)를 요구해 에이전트가 원천적으로 못 쓴다("Extension has not been invoked"). 폴백 `getDisplayMedia` 선택 창은 브라우저 자체 UI다. 매뉴얼의 "Do not attempt video recording"을 유지한다.
- **30s 리플레이의 탭 모드 보정.** 폴링은 대상 탭이 활성일 때만 프레임을 쌓는다(`use-30s-replay.ts:74`). 탭 모드에서 패널이 앞이면 프레임이 0이고, T가 앞이면 숨은 패널의 600ms 틱이 1s 이상(5분 뒤엔 분 단위)으로 throttle된다. 가이드·매뉴얼에 한계로만 적는다.
- **영역 드래그의 자동 handoff.** 패널 하단의 뷰포트·전체 페이지 버튼을 가리지 않으려고 capturing 진입 때 T를 앞으로 가져오지 않는다. 대상 탭으로의 이동은 사용자(에이전트) 몫이다.
- **패널 탭 → 제3 탭 전환 시 T 정지.** 지금도 이 경로에선 T가 계속 기록된다(`stopRecorders(패널)`은 no-op). 새 정지 동작을 도입하지 않는다. T에서 곧장 제3 탭으로 가면 멈추는 기존 계약은 그대로다.
- **같은 T에 사이드패널과 탭 모드 패널이 동시에 붙는 경우.** 한쪽 port가 끊기면 세션 키 삭제·`stopRecorders(T)`·picker `handleClear`로 상대 패널 세션이 리셋된다(`background/index.ts:91-107`). 현재 동작 그대로 두고 매뉴얼에 "한 T에 패널 하나"를 적는다.
- **마크다운 `.md` 다운로드.** 결과 확인은 미리보기 DOM으로 충분하고, 주 경로는 제출이다.
- **Radix Tabs가 mousedown에만 반응하는 문제.** 표준 동작이다. 이번 스모크에서 문제가 된 건 ego의 제어권 오판 상태뿐이다.
- **별도 창 모드 제거.** 기존 "별도 창" 경로는 그대로 동작해야 한다. 같은 창은 추가 지원이다.

## 사용자 시나리오

### S1. 에이전트 — 같은 창 탭 모드로 스크린샷 이슈 제출
1. 에이전트가 대상 페이지 탭 T를 연다. 이어서 같은 창에 `chrome-extension://<ID>/src/sidepanel/index.html`을 연다(쿼리 없음).
2. 패널이 대상 탭 선택 화면을 보여 준다. 목록에 T가 있다(같은 창 탭이 먼저). 에이전트가 T를 고르면 URL이 `?tabId=T`로 바뀌어 바인딩된다.
3. 탭 모드 안내 한 줄(로케일별 번역 + `#__BUGSHOT_AGENT__` 리터럴)이 접근성 스냅샷에 보인다. 에이전트가 매뉴얼을 읽는다.
4. 에이전트가 T로 가서 버그를 재현한다. 레코더가 돈다.
5. 에이전트가 패널 탭으로 돌아온다. 이때 T의 레코더는 **멈추지 않는다**(패널 탭이 T에 바인딩된 자기 패널이므로).
6. `[mode-screenshot]` → `[capture-method-viewport]`를 누른다.
   - 패널이 T를 잠시 활성화해 캡처하고 다시 패널 탭을 활성화한다.
   - drafting으로 넘어가고, 로그 첨부에 4단계의 로그가 있다.
7. 제목 입력 → 미리보기 → 제출.

### S2. 에이전트 — 요소 스타일 편집
1. S1의 1–3과 같다. 에이전트가 `[mode-element]`를 누르면 picking 진입과 동시에 패널이 T를 활성화한다.
2. 에이전트가 T에서 요소를 클릭한다. styling으로 넘어가고, **before 캡처가 끝난 뒤** 패널 탭이 다시 활성화된다(styling 전이가 before 캡처보다 먼저 일어나므로 phase만 보고 복귀하면 before가 깨진다).
3. 값을 편집하고 Next를 누르면, after 캡처 동안 T가 잠시 활성화됐다가 돌아온다. before/after가 둘 다 T 화면이다.

### S3. 사람 — 패널 URL을 탭으로 연 경우
S1·S2와 같은 이점을 얻는다. 지금은 캡처가 "No snapshot"·무음 idle 리셋으로 실패하는 경로다. 에이전트 안내 한 줄도 보이지만 허용한다(목표 4).

### S4. 캡처 실패 토스트 (사이드패널·탭 모드 공통)
- 캡처가 큐에서 대기하는 동안 대상 탭이 비활성이 됨 → "대상 탭이 앞에 있어야 캡처할 수 있습니다" 토스트 + 기존 복귀 동작(idle 리셋·after 없음 등) 유지. 사이드패널에선 탭을 바꾼 순간 패널이 가려져 사실상 보이지 않는다 — 기대 효과는 탭 모드 기준이다.
- 요소를 찾지 못함(요소 소실·selector 미일치·content 무응답) → "요소를 찾지 못해 캡처하지 못했습니다". 좌표 기준 강등(basis downgrade)으로 인한 의도된 스킵은 토스트하지 않고 지금처럼 "No snapshot"만 남긴다.
- rate limit 재시도 3회 소진 → "캡처 요청이 몰렸습니다. 잠시 후 다시 시도하세요".
- 그 외 → 일반 실패 문구.
- 토스트 없음: activeTab 만료(기존 다이얼로그 `onPickerPermissionExpired`가 처리 — 지연 경로의 deferred 플래그가 켜져 있을 때도 억제), 사용자 취소(`scroll capture aborted`), stale 결과 폐기(선택이 바뀐 뒤 도착한 결과).
- 한 번의 실패에 토스트는 하나다.

### 엣지 케이스
- **탭 모드인데 대상 탭이 다른 창에 있음**(기존 별도 창 경로): 이미 양쪽 다 활성이라 handoff를 하지 않는다.
- **별도 창 + 쿼리 없음**: 선택 화면이 모든 창의 탭을 보여 주므로 다른 창의 T를 고를 수 있다.
- **선택 화면에서 지원 탭이 하나도 없음**: "캡처할 수 있는 페이지 탭이 없습니다" 안내. 탭이 열리거나 닫히면 목록이 실시간으로 갱신된다.
- **패널 탭 → 제3의 탭 전환**: T는 계속 기록된다(현재 동작 유지, 비목표 참조).
- **T → 제3의 탭 전환**: T의 레코더가 멈춘다(기존 계약).
- **handoff 중 사용자/에이전트가 제3 탭으로 이동**: 캡처가 끝나도 패널을 강제로 앞으로 가져오지 않는다(T가 여전히 활성일 때만 복원).
- **handoff 중 대상 탭이 닫힘**: 캡처 실패 토스트(기타) + 패널 탭은 그대로 둔다.
- **숨은 패널 탭이 Memory Saver로 discard됨**: port 해제 → `stopRecorders(T)`. 위험으로 기록하고 실측한다.
- **사이드패널(정상 모드)**: `chrome.tabs.getCurrent()`가 `undefined`라 탭 모드 로직이 전부 비활성이다(착수 전 실측으로 확정).

## 성공 기준

- 같은 창 탭 모드에서 S1·S2가 e2e로 통과한다. 이때 spec은 캡처 트리거용 우회(`bringToFront`로 fixture를 앞에 두기·`evaluate(el.click())`)를 쓰지 않고 패널 버튼만 누른다. before/after·뷰포트 이미지는 크기·픽셀로 fixture 화면임을 확인한다.
- 같은 창 탭 모드에서 패널 탭 ↔ 대상 탭을 오간 뒤에도 대상의 console/network/action 로그가 계속 쌓인다(e2e). 변경 전 red가 실측되지 않으면 그물을 단위(배선 테스트)로 옮긴다.
- 탭 모드 전체 페이지 캡처·diff 재캡처가 성공한다(e2e 또는 수동 — tasks에 명시).
- 실패 4분류가 토스트로 뜨고, 취소·의도된 스킵·권한 만료에선 뜨지 않는다. 분류 순수 함수는 단위 테스트로, 비활성 탭 경로 1개는 e2e로 확인한다.
- 탭 모드에선 안내(`tab-mode-agent-hint`)가 보이고, 사이드패널 모드에선 탭 모드 UI(안내·선택 화면·영역 안내)가 하나도 렌더되지 않는다.
- 접힌 플랫폼 탭이 실제 Chrome에서 `getByRole("tab", { name: "Custom Webhook" })`로 잡힌다(e2e). jsdom은 클래스 단언(`sr-only` 존재·`hidden` 부재)으로 고정한다.
- `agentManual.test.ts` green. 매뉴얼의 같은 창 지원·대상 탭 선택·탭 모드 안내 주장이 소스에 바인딩돼 있다.
- 사이드패널 정상 모드에서 기존 e2e가 전부 green이다(회귀 0). 별도 창 탭 모드 e2e 1건 green.
