# 녹화 중 로그 확인 (Recording Live Logs)

## 배경

녹화(탭/화면) 중에는 Debug의 콘솔·네트워크 서브탭이 잠긴다(`DebugTab.tsx`의 `logTabsLocked = phase === "recording" || unsupported`). 그래서 사용자가 볼 수 있는 건 서브탭 트리거의 **개수 배지**뿐이다. 버그를 재현하면서 "기대한 API 호출이 잡혔나", "그 에러가 콘솔에 찍혔나"를 확인할 방법이 없다. 결국 녹화를 끝낸 뒤 트림 화면이나 초안에서야 알게 되고, 로그가 빠졌으면 처음부터 다시 녹화해야 한다.

잠근 이유는 진행 중인 버퍼를 **Clear로 지우는 것**을 막기 위해서였다(`DebugTab.tsx` 주석). 조회 자체를 막을 이유는 없었다.

## 목표

1. 녹화 중(`phase === "recording"`)에도 콘솔·네트워크 서브탭을 **읽기 전용**으로 연다. 검색, 필터, 행 펼치기, 네트워크 상세 보기는 평소와 같다.
2. 녹화 중에는 콘솔·네트워크 서브탭 하단에 **반전 표면의 플로팅 바**를 띄운다: `● 탭 녹화 중 0:45 / 2:00  [취소] [녹화 완료]`. 로그를 보는 동안에도 녹화가 진행 중이라는 사실을 패널에서 가장 강한 시각 신호로 상기시킨다.
3. 바의 [녹화 완료]·[취소]는 이슈 서브탭의 녹화 화면(`RecordingState`)과 **같은 동작**이다.
4. 녹화 중에는 서브탭 footer(`[Clear]`·`[이슈 작성]`)를 렌더하되 **disabled**로 둔다. 진행 중인 버퍼를 지우는 경로와 녹화 phase와 충돌하는 자유 작성 진입을 막는다.
5. 녹화 중에는 어느 서브탭에 있든 콘솔·네트워크 배지 개수가 실시간으로 오른다.

## 비목표 (Non-goals)

- 액션 로그 서브탭 신설. 액션 로그는 지금처럼 트림 화면과 초안에서만 본다.
- 특정 로그가 들어오면 알림을 띄우는 "감시 키워드" 기능.
- 이슈 서브탭에 바를 띄우는 것. 기존 `RecordingState` 큰 화면이 같은 정보를 이미 보여주고, 두 번 노출하면 바의 위계가 약해진다.
- 30s Replay. 녹화 phase가 아니고(폴링 프레임 버퍼) 이번 스코프 밖이다.
- 녹화 중 로그 Clear 허용.
- 범용 `FloatingBar` 컴포넌트. 소비처가 하나라 `RecordingFloatingBar`만 만들고, 관용구는 DESIGN.md에 기록한다.

## 사용자 시나리오

### S1. 녹화 중 네트워크 요청 확인
1. 사용자가 탭 녹화를 시작한다. 이슈 서브탭에 녹화 화면이 뜬다.
2. 페이지에서 버그를 재현한다. 서브탭 바의 네트워크 배지가 17 → 18로 오른다.
3. 네트워크 서브탭을 누른다. 탭이 열리고 요청 목록이 보인다. 하단에 `● 탭 녹화 중 0:45 / 2:00 [취소] [녹화 완료]` 바가 떠 있다. 그 뒤로 disabled 상태의 `[Clear]`·`[이슈 작성]`이 블러로 비친다.
4. `/api/orders`를 검색해 요청을 펼쳐 응답을 확인한다. 목록 끝까지 스크롤하면 마지막 행이 바 위로 완전히 올라온다.
5. 바에서 [녹화 완료]를 누른다. 녹화가 정지되고 서브탭이 **issue로 이동**하며 트림 화면이나 초안으로 이어진다.

### S2. 녹화 중 취소
1. 콘솔 서브탭에서 바의 [취소]를 누른다.
2. 녹화가 폐기되고 phase가 idle로 돌아간다. **콘솔 서브탭에 그대로 머문다**. 로그는 보존되고(`cancelRecording`의 `preserveLogs`), 바는 사라지며 `[Clear]`·`[이슈 작성]`이 다시 활성화된다.

### S3. 자동 종료
1. 콘솔 서브탭에서 로그를 보던 중 최대 길이(2:00)에 닿거나, 화면 녹화라면 브라우저의 "공유 중지"를 누른다.
2. S1-5와 똑같이 서브탭이 issue로 이동하고 drafting으로 이어진다.

### S4. 테마
- 앱이 라이트 테마면 바는 **어두운** 반투명 표면, 앱이 다크 테마면 **밝은** 반투명 표면이다. 설정에서 테마를 바꾸거나 `system` 모드에서 OS 테마가 바뀌면 바도 즉시 따라 뒤집힌다.

### S5. 좁은 패널 / 긴 로케일
- 폭이 부족하면 라벨("탭 녹화 중")만 말줄임되고, 빨간 점, 시간, 두 버튼은 그대로 남는다.

### 엣지 케이스
- **녹화 중 미지원 페이지로 이동**: 지금처럼 `unsupported`가 로그 탭을 잠그고 서브탭을 issue로 돌려보낸다(기존 effect 그대로).
- **녹화 중 cross-origin 이동**: 로그는 유지된다(`shouldPreserveBackgroundLogs`). 바와 탭 상태는 그대로다.
- **로그 0건**: 기존 빈 상태 화면 위에 바가 뜬다. 빈 상태는 가운데 정렬이라 가려지지 않는다.

## 성공 기준

- 녹화 중 콘솔·네트워크 서브탭 트리거가 활성 상태이고, 클릭하면 로그 목록이 렌더된다.
- 녹화 중 두 서브탭에 플로팅 바가 보이고, 이슈 서브탭에는 바가 없다.
- 바의 [녹화 완료]·[취소]가 각각 `videoRecorder.stopRecording()`·`cancelRecording()`을 호출한다.
- 녹화 중 `[Clear]`·`[이슈 작성]`이 disabled다.
- phase가 drafting·previewing·done으로 바뀌면 서브탭이 issue로 바뀐다. idle(취소)로 바뀌면 현재 서브탭이 유지된다.
- 앱 테마와 바 테마가 항상 반대다.
- 최대 폭과 최소 폭 모두에서 바가 패널 바깥으로 넘치지 않는다(최소 폭은 수동 확인, 아래 tasks 참조).
- `pnpm typecheck`·`pnpm test` green.
