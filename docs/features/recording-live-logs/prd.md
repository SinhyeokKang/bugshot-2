# 녹화 중 로그 확인 (Recording Live Logs)

## 배경

녹화(탭/화면) 중에는 Debug의 콘솔·네트워크 서브탭이 잠긴다(`DebugTab.tsx`의 `logTabsLocked = phase === "recording" || unsupported`). 그래서 사용자가 볼 수 있는 건 서브탭 트리거의 **개수 배지**뿐이다. 버그를 재현하면서 "기대한 API 호출이 잡혔나", "그 에러가 콘솔에 찍혔나"를 확인할 방법이 없다. 결국 녹화를 끝낸 뒤 트림 화면이나 초안에서야 알게 되고, 로그가 빠졌으면 처음부터 다시 녹화해야 한다.

잠근 이유는 진행 중인 버퍼를 **Clear로 지우는 것**을 막기 위해서였다(`DebugTab.tsx` 주석). 조회 자체를 막을 이유는 없었다.

## 목표

1. 녹화 중(`phase === "recording"`)에도 콘솔·네트워크 서브탭을 **읽기 전용**으로 연다. 검색, 필터, 행 펼치기, 네트워크 상세 보기는 평소와 같다.
2. 녹화 중에는 콘솔·네트워크 서브탭 하단에 **반전 표면의 플로팅 바**를 띄운다: `● 탭 녹화 중  0:45  [✕] [완료]`. 이슈 서브탭을 떠나 로그를 보는 동안에도 녹화 상태(빨간 점·경과 시간)와 정지·취소 수단이 항상 화면에 보인다.
3. 바의 [완료]·[✕ 취소]는 이슈 서브탭의 녹화 화면(`RecordingState`)과 **같은 동작**이다(같은 `videoRecorder` 함수, 확인 단계 없음).
4. 녹화 중에는 서브탭 footer(`[Clear]`·`[이슈 작성]`)를 렌더하되 **disabled**로 둔다. 진행 중인 버퍼를 지우는 경로와 녹화 phase와 충돌하는 자유 작성 진입을 막는다.
5. 녹화 중 어느 서브탭에 있든 콘솔·네트워크 배지가 계속 오른다 — 서브탭을 옮겨도 로그 갱신 경로(레코더 stream + 1.5s 보조 폴링)가 끊기지 않는다.

## 비목표 (Non-goals)

- 액션 로그 서브탭 신설. 액션 로그는 지금처럼 트림 화면과 초안에서만 본다.
- 특정 로그가 들어오면 알림을 띄우는 "감시 키워드" 기능.
- 이슈 서브탭에 바를 띄우는 것. 기존 `RecordingState` 큰 화면이 같은 정보를 이미 보여주고, 두 번 노출하면 바의 위계가 약해진다.
- 30s Replay 버퍼링 중 바 표시. 리플레이 버퍼링은 phase가 idle이라 로그 탭은 이미 열려 있고, 녹화 세션이 아니므로 **의도적으로 바를 띄우지 않는다**.
- 녹화 중 로그 Clear 허용.
- 바의 [취소] 확인 다이얼로그. `RecordingState`의 취소와 같은 즉시 폐기로 둔다(같은 함수·같은 UX).
- 바에 그리기 툴(펜·사각형·형광펜) 노출. 툴바는 `RecordingState`에만 있고, 펜을 켠 채 로그 탭으로 가면 페이지에서 Esc로 끈다.
- 범용 `FloatingBar` 컴포넌트. 소비처가 하나라 `RecordingFloatingBar`만 만들고, 관용구는 DESIGN.md에 기록한다.

## 사용자 시나리오

### S1. 녹화 중 네트워크 요청 확인
1. 사용자가 탭 녹화를 시작한다. 이슈 서브탭에 녹화 화면이 뜬다.
2. 페이지에서 버그를 재현한다. 서브탭 바의 네트워크 배지가 17 → 18로 오른다.
3. 네트워크 서브탭을 누른다. 탭이 열리고 요청 목록이 보인다. 하단에 `● 탭 녹화 중  0:45  [✕] [완료]` 바가 떠 있다. disabled 상태의 `[Clear]`·`[이슈 작성]`은 바 뒤에 완전히 덮여 보이지 않는다(키보드·보조기기 진입만 막는다).
4. `/api/orders`를 검색해 요청을 펼쳐 응답을 확인한다. 목록 끝까지 스크롤하면 마지막 행이 바 위로 완전히 올라온다.
5. 바에서 [완료]를 누른다. 정지 처리(썸네일·로그 settle, 수백 ms) 동안 바의 시간은 마지막 값에 머문다. 이어서 서브탭이 **issue로 이동**하고 트림 화면으로 이어진다. 트림 중에는 서브탭 바가 숨겨져 로그 탭으로 돌아갈 수 없다(트림 화면 자체에 로그 표시가 있다).

### S2. 녹화 중 취소
1. 콘솔 서브탭에서 바의 [✕ 취소]를 누른다.
2. 녹화가 즉시 폐기되고 phase가 idle로 돌아간다. **콘솔 서브탭에 그대로 머문다**. 로그는 보존되고(`cancelRecording`의 `preserveLogs`), 바는 사라지며 `[Clear]`·`[이슈 작성]`이 다시 활성화된다. 키보드로 눌렀다면 포커스는 콘솔 서브탭 트리거로 돌아간다.

### S3. 자동 종료
1. 콘솔 서브탭에서 로그를 보던 중 최대 길이(2:00)에 닿거나, 화면 녹화라면 브라우저의 "공유 중지"를 누른다.
2. S1-5와 똑같이 서브탭이 issue로 이동하고 트림 화면으로 이어진다.

### S4. 테마
- 앱이 라이트 테마면 바는 **어두운** 반투명 표면, 앱이 다크 테마면 **밝은** 반투명 표면이다. 설정에서 테마를 바꾸거나 `system` 모드에서 OS 테마가 바뀌면 바도 즉시 따라 뒤집힌다.

### S5. 좁은 패널 / 긴 로케일
- 바는 처음부터 좁은 폭에 맞춘 구성이다: 시간은 경과만(`0:45` — 상한은 이슈 서브탭 `RecordingState`가 보여준다), 취소는 아이콘 버튼(✕, 툴팁·`aria-label` "취소"), 완료는 짧은 전용 라벨(완료/Stop/Arrêter/Detener/Stoppen).
- 그래도 폭이 부족하면 라벨("탭 녹화 중")만 말줄임되고, 빨간 점·시간·두 버튼은 그대로 남는다. 최소 패널 폭(약 320px)에서 5개 로케일 모두 바가 패널 밖으로 넘치지 않는다.

### 엣지 케이스
- **녹화 중 미지원 페이지로 이동**: 지금처럼 `unsupported`가 로그 탭을 잠그고 서브탭을 issue로 돌려보낸다(기존 effect 그대로).
- **녹화 중 cross-origin 이동**: 로그는 유지된다(`shouldPreserveBackgroundLogs`). 바와 탭 상태는 그대로다.
- **화면 녹화 중 다른 탭으로 이동**: 로그는 녹화를 시작한 탭 기준이다. 탭을 전환하면 background가 원래 탭 레코더를 멈추고(`tab-bindings.ts` `stopRecorders`) 원래 탭의 패널이 닫히며, 다른 탭의 로그는 수집하지 않는다. 원래 탭으로 돌아오면 레코더가 재주입된다(ARCHITECTURE "활성 게이트"). 복귀 시 서브탭·바가 유지되는지는 패널 문서가 살아 있다는 전제다(수동 확인).
- **화면 녹화에는 패널이 찍힌다**: `getDisplayMedia`가 화면 전체를 녹화하므로 녹화 중 로그 탭을 열면 헤더·바디(레코더 단계 마스킹만 적용)가 영상에 남는다. `logsAttach`를 꺼도 영상에는 남는다. 탭 녹화는 해당 없음. 가이드에 한 줄 안내한다.
- **로그 0건**: 기존 빈 상태 화면 위에 바가 뜬다. 빈 상태는 가운데 정렬이라 가려지지 않는다.
- **네트워크 상세를 펼친 채 종료**: 취소(S2)면 서브탭이 유지돼 상세 펼침 상태도 그대로 남는다. 완료(S1-5)면 서브탭이 issue로 바뀌며 로그 탭 콘텐츠가 언마운트돼(Radix `TabsContent`) 다음 진입 시 상세는 닫힌 상태다.

## 성공 기준

- 녹화 중 콘솔·네트워크 서브탭 트리거가 활성 상태이고, 클릭하면 로그 목록이 렌더된다.
- 녹화 중 두 서브탭에 플로팅 바가 보이고, 이슈 서브탭에는 바가 없다.
- 바의 [완료]·[✕ 취소]가 각각 `videoRecorder.stopRecording()`·`cancelRecording()`을 호출한다.
- 녹화 중 `[Clear]`·`[이슈 작성]`이 disabled다.
- phase가 `hideSubTabs` 대상(styling·drafting·previewing·done)으로 바뀌면 서브탭이 issue로 바뀐다. idle(취소)로 바뀌면 현재 서브탭이 유지되고 포커스가 그 서브탭 트리거로 돌아간다.
- [완료] 후 phase가 바뀌기 전까지 바의 시간이 0:00으로 떨어지지 않는다.
- 앱 테마와 바 테마가 항상 반대다.
- 최소 폭(320px)에서 5개 로케일 모두 바가 패널 바깥으로 넘치지 않는다(e2e로 판정 — tasks 참조).
- `pnpm typecheck`·`pnpm test` green, 신규 e2e spec green.
