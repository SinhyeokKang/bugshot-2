# 본문 구성 빠른 접근 (Body composition quick access)

## 배경

이슈 본문의 섹션 구성(사용 여부·순서)은 **설정 > 이슈 > 본문 구성**에서만 바꿀 수 있다. 그런데 "이 섹션은 이번 이슈에 필요 없다"는 판단이 서는 시점은 설정 화면이 아니라 **작성 중이거나 프리뷰를 보는 순간**이다.

지금은 활성화된 섹션을 빈 값으로 두고 넘어가면 표시면과 제출 본문에 각각 빈 값 표기가 남는다.

| 표면 | 표기 |
|---|---|
| 프리뷰 패널 · 이슈 상세 | **"비어 있음"**(`common.empty`) |
| 제출·복사 본문 (마크다운/ADF/Notion) | **`(없음)`**(`src/sidepanel/lib/buildIssueMarkdown.ts:298,303` 및 나머지 7개 플랫폼 빌더 동일) |

이 표기는 "작성자가 의도적으로 비웠다"는 신호라서 유지할 가치가 있고, 조용히 드롭하면 `media` 블록 위치까지 흔들려 골든 테스트를 전면 갱신해야 한다. 따라서 해결책은 출력 규칙 변경이 아니라 **설정 접근 경로를 작성 흐름 안으로 끌어오는 것**이다.

## 목표

- 이슈 작성 패널(drafting)과 프리뷰 패널(preview) 푸터에서 **한 번의 클릭으로 본문 구성 설정을 열 수 있다**.
- 다이얼로그에서 섹션 **사용 여부 토글**과 **순서 재정렬**을 모두 할 수 있다.
- 변경은 즉시 반영되어, 다이얼로그를 닫으면 뒤의 작성/프리뷰 패널이 갱신된 구성으로 보인다.
- 변경은 전역 영속되어 **설정 > 이슈 > 본문 구성**과 항상 같은 값을 가리킨다(양방향 단일 출처).

## 비목표 (Non-goals)

- 빈 섹션의 `(없음)`·"비어 있음" 출력 규칙 변경. 현행 유지한다.
- 이슈별(per-issue) 섹션 구성. 이 설정은 전역이고, 과거 이슈의 상세·복사 본문에도 소급 적용된다(현행 동작 그대로).
- `DraftDetailDialog`(제출 완료 이슈 상세)에 같은 진입점 추가. 소급 변경을 "이 이슈만 고치는 것"으로 오해할 여지가 커서 제외한다.
- 섹션 라벨 편집(`labelOverride`), 섹션 추가/삭제. 현재 설정 탭에도 UI가 없다.
- 다이얼로그 취소(rollback). 스토어 액션이 즉시 persist이고 이 모델이 설정 탭과 동일하기 때문이다. **단 `resetIssueSectionOrder`는 순서만 되돌리고 `enabled`는 건드리지 않으므로, 실수로 끈 섹션의 되돌리기 경로는 "직접 다시 켜기"뿐이다.**
- **첨부(attachments) 설정.** 첨부는 `issueSections` 항목이 아니라 별도 전역 설정(`attachmentsEnabled`)이고 렌더도 `bodyBlocks` 밖 최하단 고정이다. 이름이 "본문 구성"이라 기대될 수 있으나 이번 다이얼로그에 넣지 않는다.
- **`useReproPrefill` 게이트 동작 변경.** 별도 티켓으로 분리한다(아래 엣지 케이스 참조). 이번 변경은 진입점 추가에 한정한다.
- 전역 설정임을 **경고**하는 캡션/고지 문구. 넣지 않는다. (다이얼로그가 무엇을 하는 화면인지 알리는 `DialogDescription` 한 줄은 접근성 요구라 별개로 넣는다 — 소급 적용 경고는 담지 않는다.)

## 사용자 시나리오

### 1. 작성 중 불필요한 섹션 끄기

1. 캡처를 마치고 이슈 작성 패널에 들어온다.
2. **비고** 섹션이 켜져 있지만 이번 이슈엔 쓸 내용이 없다.
3. 푸터의 `⚙`(Settings2) 버튼을 누른다 → **본문 구성** 다이얼로그가 열린다.
4. 비고 스위치를 끈다.
5. **확인**을 눌러 닫는다 → 작성 패널에서 비고 입력 영역이 사라진다.
6. 제출된 본문에 비고 섹션이 없다.

### 2. 프리뷰에서 빈 섹션을 보고 끄기

1. 프리뷰 패널에서 **기대 결과** 섹션이 **"비어 있음"**으로 렌더된 걸 본다. (이 섹션을 그대로 제출하면 본문에는 `(없음)`이 남는다.)
2. 푸터 `⚙` → 기대 결과 스위치 off → **확인**.
3. 프리뷰 본문이 즉시 갱신되어 해당 섹션이 사라진다.
4. 그대로 **이슈 제출**을 누른다.

### 3. 순서 재정렬

1. 작성 중 미디어를 맨 위로 올리고 싶다.
2. 푸터 `⚙` → 드래그 핸들(또는 키보드: 핸들 포커스 → Space → 방향키 → Space)로 **미디어 · 로그**를 최상단으로 이동.
3. **확인** → 작성 패널의 섹션 순서가 그대로 바뀐다. **입력해 둔 텍스트는 모두 유지된다.**

### 4. 껐다 다시 켜기 (데이터 보존)

1. 설명 섹션에 텍스트를 입력한 상태에서 설명을 끈다 → 입력 영역이 사라진다.
2. 다시 켠다 → 입력해 둔 텍스트가 그대로 돌아온다.
   (`draft.sections[id]`는 유지되고 `bodyBlocks`가 렌더만 건너뛴다.)

### 5. 설정 탭과의 동기

1. 다이얼로그에서 비고를 끈다.
2. 설정 > 이슈 > 본문 구성으로 이동한다 → 비고가 꺼져 있다.
3. 설정 탭에서 다시 켠 뒤 이슈 작성으로 돌아오면 비고 섹션이 있다.

### 엣지 케이스

- **미디어 행**: 스위치가 없다(순서만 조정). 본문 emit은 데이터 기반이라 on/off 대상이 아니다.
- **기본 순서일 때**: 다이얼로그 푸터의 **기본 순서 복원** 버튼이 `disabled`.
- **AI 초안 / 재현 과정 자동채움 로딩 중**: 푸터 `⚙` 버튼이 `disabled`. 이유는 **로딩 중 UI 조작 차단**이다 — AI 머지(`mergeAiSectionsPreservingBlocks`)는 요청 시작 시점의 `issueSections` 스냅샷을 쓰고 prev 키를 전부 순회하므로 구성이 바뀌어도 손상되지 않는다.
- **다이얼로그를 열어 둔 채 AI가 시작되는 경우**: 버튼 `disabled`는 "로딩 중 열기"만 막는다. 이 경우 다이얼로그는 열린 채로 두고 조작도 허용한다(머지가 안전하므로).
- **제목이 비어 있을 때**: `⚙` 버튼은 눌린다(미리보기 버튼의 `titleMissing` 조건을 따라가지 않는다).
- **재현 과정을 작성 중에 켰을 때**: **현행 동작 그대로 그 자리에서 AI 자동채움이 발화한다.** 지금까지는 설정 탭을 거쳐야 해서 사실상 도달 불가였지만 이번 진입점이 생기면 흔한 경로가 된다. 이 타이밍을 "작성 화면 진입 시점 구성으로 고정"하는 변경은 훅 회귀 위험이 커서 **별도 티켓**으로 분리한다.
- **media 제외 4개 섹션을 전부 off**: 본문이 미디어·로그만 남는다. drafting/preview 렌더와 8개 빌더 출력이 성립해야 한다.

## 성공 기준

- drafting·preview 두 패널 푸터에서 다이얼로그를 열어 토글·재정렬할 수 있다.
- 다이얼로그에서 바꾼 값이 설정 탭에, 설정 탭에서 바꾼 값이 다이얼로그에 즉시 반영된다(`chrome.storage` 영속).
- 순서를 바꾸고 닫아도 각 섹션에 입력해 둔 텍스트가 유지된다. **포커스·selection 유지는 e2e로 고정한다**(design.md 위험 요소 참조 — 현재 미검증).
- 사이드패널 **320px** 폭·**en 로케일**에서 drafting·preview 푸터가 겹치거나 잘리지 않는다.
- 기존 e2e(`body-composition-reorder`·`settings-sections`·`repro-prefill`)가 그대로 green이다.

> 제품 지표(다이얼로그 경로 사용 비율, 빈 섹션 제출률 변화)는 **측정하지 않는다** — 현재 PostHog 집계에 해당 이벤트가 없고, 이번 변경에 이벤트를 추가하지 않는다.
