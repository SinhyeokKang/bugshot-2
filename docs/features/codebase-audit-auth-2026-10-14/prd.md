# 감사 A01·A03 인증 경계 복구

## 배경
[감사 리포트](../codebase-audit-2026-10-14/report.md)의 A01은 기존 요청이 재연결 계정의 인증으로 실행되는 문제이고, A03은 서로 다른 플랫폼의 토큰 갱신과 패널 설정 저장이 같은 envelope를 덮는 문제다.

## 목표
- 요청의 신원·grant를 토큰 회전 중에도 유지한다. 다른 grant의 인증·진행 중 refresh 결과를 재사용하지 않는다.
- 여러 플랫폼 refresh와 패널 설정 변경이 겹쳐도 무관한 최신 인증을 잃지 않는다.
- 같은 grant의 정상 회전·동시 요청 dedup과 기존 연결/설정 UX를 유지한다.

## 비목표
새 인증 방식·권한·서버·외부 API·설정 UI를 추가하지 않는다. 앱 UI 설정 전반의 병합이나 issue 저장소 재설계는 범위 밖이다.

## 사용자 시나리오
1. A 요청 중 B 계정/사이트로 재연결한다. A의 401/refresh가 늦게 돌아와도 B 인증으로 A 요청을 보내지 않는다.
2. 같은 계정으로 다시 연결해도 새 grant가 이전 요청·refresh와 구분된다.
3. Linear와 GitLab refresh가 겹쳐도 양쪽 최신 토큰이 보존된다.
4. refresh 중 제목 접두사·플랫폼 기본값을 수정해도 토큰이 되돌아가지 않는다.
5. 연결 해제/재연결 중 오래된 설정 저장·refresh가 끝나도 인증이 부활하거나 새 grant를 덮지 않는다.

## 성공 기준
실제 fetch 대상·Authorization과 최종 영속 envelope를 제어 가능한 비동기 테스트로 검증한다. 두 독립 패널 저장 주체와 background writer를 포함한다. typecheck/test/sync 모두 성공한다.
