전 배치(`audit-refactor-4/5/6`)와 같은 형태다 — 개별로는 작지만 흩어져 있어 각각을 따로 손대면 컨텍스트 로딩 비용이 수정 비용을 넘는다. 묶어서 **논리 단위(G그룹)**로 재편하고, 그룹 안에서 같은 파일·같은 그물을 공유한다.

이번 감사가 직전 배치들과 다른 점은 **에러 경로에 몰려 있다**는 것이다. 🟡 33건 중 11건이 "예외가 나면 응답이 영영 안 온다 / 실패가 성공으로 판정된다 / 마스킹 게이트가 우회된다" 계열이다. 이건 정상 경로에서 안 보이고 사용자에게는 "가끔 멈춘다"로만 나타나므로, 이번 배치의 P0는 전부 여기에 배정한다.

## 목표

1. **응답 채널이 예외로 매달리는 경로를 없앤다.** `picker.scrollCaptureTo`·css 캐시 로드·picker 보강 IIFE 3경로에서, 예외가 나도 사이드패널의 `await`가 유한 시간에 풀린다.
2. **실패를 성공으로 읽는 응답 계약을 고친다.** OAuth 에러 레인 오분류 1건, 토큰 응답 무검증 1건, 업로드 결과 판별자 4종.
3. **마스킹 게이트 우회 1건을 막는다.** `aria-labelledby`가 공백 구분 다중 ID일 때 라벨을 못 구해 민감 필드가 액션 로그에 원문으로 실리는 경로.
4. **`store`가 사이드패널 컴포넌트 트리를 참조하지 않게 한다.** value import 2건 제거 — typecheck도 테스트도 안 잡는 축이라 지금 끊는다.
5. **드리프트가 이미 발생한 단일 출처 4건을 합친다.** `escapeHtml`·`imageCell`·`MarkdownIt` 설정·frozen phase 집합.
6. **공용 콤보박스가 있는데 재구현한 9벌을 지배 패턴으로 수렴시킨다.**
7. **컨벤션 이탈 국소 수정 10건** — 🔴 툴팁 1건 포함.
8. **회귀를 재발 방지 그물로 고정한다.** 새 순수 함수·헬퍼는 테스트 선행, 브라우저 실동작에 걸린 것만 수동으로 남긴다.

## 사용자 시나리오

이 배치는 대부분 내부 정리라 사용자 눈에 보이는 변화는 셋뿐이다.

**S1 — 연동 없이 이슈 제출을 누른다 (🔴#1).**
1. 연동을 하나도 안 한 사용자가 이슈 작성을 마치고 `[이슈 제출]` 버튼에 커서를 올린다.
2. **현재**: 버튼이 비활성이고 아무 설명이 없다. `title`이 붙어 있지만 `disabled:pointer-events-none` 때문에 hover 자체가 죽어 툴팁이 뜨지 않는다. 사용자는 왜 못 누르는지 모른다.
3. **변경 후**: `IssueTab.tsx:368`과 같은 방식으로 툴팁이 떠서 "연동된 플랫폼이 없습니다"를 읽는다.
4. 엣지: 키보드 사용자는 `aria-disabled`라 포커스를 받고 스크린리더가 상태와 이유를 함께 읽는다. 클릭은 `onClick` 가드로 막는다(`aria-disabled`는 클릭을 막지 않는다).

**S2 — Linear 이슈 상태를 바꾸려 한다 (#17).**
1. 이슈 목록에서 Linear 배지를 눌러 상태 팝오버를 연다.
2. 팀에 상태가 하나도 안 잡히거나 조회가 빈 배열을 주면 **현재**는 빈 팝오버가 뜬다(로딩 스피너가 사라진 뒤 아무것도 없음).
3. **변경 후**: Jira(`issueList.jira.noTransitions`)·Notion과 같은 형태의 안내 문구가 뜬다.

**S3 — 페이지 전체 캡처 중 예외가 난다 (#5).**
1. 긴 페이지에서 "페이지 전체" 캡처를 시작한다.
2. 타일 중간에 content 쪽에서 예외가 난다(`mergePositionedCandidates`가 이상한 DOM에서 throw 등).
3. **현재**: `resolve`가 안 불려 사이드패널이 그 타일에서 영원히 대기한다. 진행률이 멈추고 취소 외엔 빠져나갈 길이 없다.
4. **변경 후**: 응답이 `undefined`로 닫히고 오케스트레이터의 기존 `if (!ack) throw` 경로를 타 "캡처 실패"로 정상 종료한다 — **잘못된 이미지를 성공으로 넘기지 않는다는 기존 계약은 유지**된다.

**S4 — 액션 로그에 민감 필드가 실린다 (#12).**
1. 결제·로그인 폼에서 `<label id="l1">카드</label><label id="l2">번호</label><input aria-labelledby="l1 l2">` 구조를 쓴다(다중 참조는 접근성 권장 패턴이다).
2. **현재**: `getElementById("l1 l2")`가 `null`이라 라벨 텍스트를 못 구하고, `SENSITIVE_NAME_RE` 게이트가 라벨을 근거로 삼지 못해 값이 원문으로 액션 로그에 들어간다. 그 로그는 이슈 본문으로 나간다.
3. **변경 후**: 공백으로 쪼개 각 ID를 조회·연결한 텍스트로 게이트를 통과시켜 `***`로 마스킹된다.

## 위험 요소 (PRD 수준)

**클론군 2건을 제외한 근거 — 판정 기준 "사정거리가 이름값보다 좁은가".**
`DROPPED.md` audit-refactor-6 ③이 `ConnectButton` 추출을 기각한 논리가 그대로 적용된다.

- **#27 PatDialog 6벌**: `{Asana,Github,Gitlab,Clickup}ConnectForm`의 `PatDialog`와 `{Linear,Jira}ConnectForm`의 `ApiKeyDialog`는 골격이 같지만, Jira는 이미 `PlatformConnectFlow`를 안 쓰고 레거시 메시지명(`oauth.start`)을 유지하는 별종이고(⚪43), Slack은 술어가 다르다. **6벌 중 4만 걷고 패턴 중복은 남긴다** — 추출 자체가 새 비대칭을 만든다.
- **#26 배지 셸 7벌**: audit-refactor-6 G5가 이미 `BadgeFallback`(공통 폴백 배지)을 뽑아갔고, 남은 63~106줄은 파일마다 메시지 타입·patch 필드가 다르다. 추출 대상을 새로 설계해야 하는 작업이지 "이미 있는 공용으로 수렴"이 아니다.
- 반면 **#28·#29(콤보박스 9벌)는 포함한다** — `SingleLazyCombobox`·`useLazyListOnOpen`·`useDebouncedSearch`가 **이미 있고**, `githubFields/LabelCombobox`·`gitlabFields/LabelCombobox`가 **이미 그걸 쓴다**. 지배 패턴이 저장소 안에 존재하므로 "수렴"이지 "설계"가 아니다.

**#34의 사정거리도 같은 축에서 좁혔다.** sidepanel은 `@/sidepanel/` 441건 vs 상대경로 502건, **혼용 파일 70개**다. 어느 쪽으로 통일해도 943개 import 문을 건드리고, 그 diff 안에서 진짜 회귀를 못 본다. 이탈이 명백한 2건(`background/lib/createRefreshRunner.ts` 1줄, `types/picker.ts` 3줄 — 각각 해당 패키지에서 **유일한** 이탈)만 고치고, 나머지는 측정치를 `design.md`에 기록한 뒤 신규 유입만 소스 스캔 테스트로 막는다.

**나머지 위험은 design.md "위험 요소"로 내린다** (번들 경계 검증 수단 부재, content 청크에 `@/lib` 유입, `withLocale` 구간 store write, 브라우저 실동작 미검증 3건).
