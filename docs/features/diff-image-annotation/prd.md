# diff table before/after 이미지 어노테이션

## 배경

element 모드로 잡은 버그는 리포트에서 **before/after 스냅샷 한 쌍**으로 전달된다. 그런데 이 두 장에는 지금 주석을 달 수 없다 — 확장 안에서 주석이 가능한 이미지는 스크린샷 캡처본(`screenshotRaw`)과 본문에 삽입한 인라인 이미지뿐이다.

문제는 element 캡처가 **가장 주석이 필요한 이미지**라는 점이다. 캡처 범위가 요소 bbox+24px이거나 의미 단위 조상 컨테이너라, 이미지 안에 요소가 여러 개 들어간다(다이얼로그·테이블 행·리스트 아이템). "이 버튼의 padding이 문제"라는 걸 이미지만으로는 지목할 수 없어서, 지금은 diff table의 prop 행을 읽어야만 어디를 봐야 하는지 알 수 있다. 리포트를 받는 사람(개발자·디자이너)이 이미지를 먼저 보는 순서와 어긋난다.

주석 기능 자체는 이미 있다(`AnnotationOverlay` — Konva 캔버스, 도형·텍스트·줌/팬). 진입점만 없다.

**촉발 신호**: 우리 가이드가 이미 우회를 권하고 있다 — `guide/ko/element/picker.md:30`은 "스크린샷에 주석을 달아 전달하는 편이 빠릅니다"라고 안내한다. 요소 캡처로 잡은 버그를 지목하려면 같은 화면을 스크린샷 모드로 다시 찍으라는 뜻이고, 그건 문제가 실재한다는 문서 증거다.

## 목표

- element 모드 drafting에서 diff table의 **before 이미지와 after 이미지 각각**에 주석을 달 수 있다.
- 주석을 단 뒤에도 **원본으로 되돌릴 수 있다**(주석 제거).
- 이슈로 제출되는 이미지, 미리보기에 보이는 이미지, AI 초안에 첨부되는 이미지가 **모두 주석본**이다 — 한 규칙(`annotated ?? raw`)으로 수렴한다.
- 주석 UI는 **아이콘·순서·hover 노출 규칙이 본문 인라인 이미지와 같다**(버튼 구성은 다르다 — 인라인은 3개, 여기는 2개). 사용자가 두 번 배우지 않는다.

## 비목표 (Non-goals)

- **저장된 초안 상세(`DraftDetailDialog`)·미리보기(`PreviewPanel`)에서의 주석 *편집*.** 두 화면도 같은 `StyleChangesTable`을 렌더하지만 편집 UI 없이 남긴다. 단 **표시는 주석본이다** — `PreviewPanel`이 원본을 보여주고 제출물만 주석본이면 미리보기가 미리보기가 아니게 된다. 스크린샷 주석(`annotation-edit`)이 `DraftingPanel` 전용인 것과 같은 급이다. (**주의**: 인라인 이미지 주석은 `TiptapEditor`가 `DraftEditDialog`에서도 마운트돼 저장된 초안에서도 열린다 — 이 기능은 그보다 좁은 범위다.)
- **주석 결과 이미지의 다운스케일·재압축.** 주석본은 원본과 같은 해상도로 만든다(`AnnotationOverlay`가 `pixelRatio: 1` + natural 좌표 Stage). 세션 쿼터 승인선(아래 성공 기준)을 못 넘으면 그때 픽셀 캡을 재검토한다.
- **주석 원본을 이슈에 함께 첨부하기.** 올라가는 건 주석본 한 장뿐이다.
- **주석 좌표의 재캡처 추종.** after가 다시 찍히면 주석은 버린다(아래 시나리오 4).
- **주석 데이터(도형 목록) 보관.** 결과 이미지만 남긴다 — 인라인 이미지·스크린샷과 동일하게 "주석 후 이미지를 다시 열면 그림 위에 이어 그린다".
- 버퍼 카드(`StyleChangesDialog`)의 행 초기화 UI 변경.

## 사용자 시나리오

### 1. before 이미지에 주석 (기본 플로우)

1. element 모드로 요소를 고르고 스타일을 수정한 뒤 `[다음]`으로 drafting에 들어온다.
2. `변경 사항 (selector)` 섹션의 diff table 첫 행에 before/after 스냅샷 두 장이 있다.
3. before 이미지에 마우스를 올리면 우상단에 `[연필]` 버튼이 나타난다.
4. 누르면 주석 오버레이가 뜬다(본문 인라인 이미지와 같은 화면).
5. 화살표를 그리고 `[완료]`를 누르면 오버레이가 닫히고 diff table의 before 이미지가 주석본으로 바뀐다.
6. 다시 마우스를 올리면 버튼이 `[주석 제거][주석 수정]` 두 개다.

**버튼 문구는 같은 화면의 스크린샷 주석 버튼과 같은 계열**(`draft.addAnnotation`/`draft.editAnnotation`/`draft.removeAnnotation`)을 쓴다. 인라인 이미지 계열(`editor.image.*` — "주석 달기"/"원본 복원")을 쓰면 같은 화면 안에서 같은 아이콘에 다른 문구가 뜨고, add/edit 분기가 없어 재주석 때도 "주석 달기"가 된다.

### 2. 주석 제거

1. 주석이 있는 이미지에 마우스를 올려 `[주석 제거]`를 누른다.
2. 이미지가 즉시 원본으로 돌아가고 버튼이 `[주석 추가]` 하나로 줄어든다.
3. 확인 다이얼로그는 없다 — 다시 주석하면 되고, 스크린샷 주석 제거(`annotation-remove`)도 즉시 실행이다.

### 3. 재주석 (주석 위에 이어 그리기)

1. 주석이 있는 이미지의 `[주석 수정]`을 누른다.
2. 오버레이는 **주석본**을 배경으로 연다(원본이 아니다). 스크린샷 주석의 `screenshotAnnotated ?? screenshotRaw`와 같은 규칙.
3. 도형을 더 그려 `[완료]`하면 그 결과가 새 주석본이 된다. 원본은 그대로 보관돼 `[주석 제거]`는 여전히 최초 원본으로 되돌린다.

### 4. after 재캡처 — 주석 폐기

after 이미지는 사용자가 스타일을 더 고치면 다시 찍힌다. 새로 찍힌 픽셀 위에 옛 좌표의 화살표가 남으면 엉뚱한 곳을 가리키고, **그건 주석이 없는 것보다 나쁘다.**

폐기 규칙은 지점 열거가 아니라 **값 비교** 하나다: `afterImage`가 실제로 다른 값으로 바뀌면 `afterAnnotated`를 버린다. 지점을 세는 방식으로는 규율이 안 선다 — 세어 보면 세 곳이고, 그중 하나는 같은 함수가 정반대 규율을 요구하기 때문이다.

| 커밋 지점 | 상황 | 새 이미지인가 |
|---|---|---|
| `setAfterImage` (`StyleEditorPanel`의 `[다음]`) | 스타일 확정 후 재캡처 | 예 → 폐기 |
| `patchBufferedElement({ afterImage })` | 버퍼 카드 행 초기화 후 재캡처 | 예 → 폐기 |
| `bufferCurrentElement(after, …)` — `useBufferThenSwitch` | repick·DOM 트리 이동 시 **새로 찍은** after를 버퍼에 적재 | 예 → 폐기 |
| `bufferCurrentElement(state.afterImage, …)` — `picker-control`의 `rebindStylingSession` | 세션 복원 왕복. **같은 이미지**를 그대로 넣는다 | 아니오 → 보존 |

값 비교 하나면 위 4행이 전부 자동으로 갈린다. `backToStyling`은 별도 규칙을 두지 않는다 — 이 액션이 이미 `afterImage: null`을 세팅하고, styling에서 drafting으로 돌아오는 유일한 통로인 `handleNext`가 dirty 체크 없이 **항상** `setAfterImage`를 부르므로, "스타일을 바꾸지 않은 왕복에서 주석을 보존한다"는 약속은 지켜질 창이 없다. 지킬 수 없는 약속을 문서에 남기면 그 자리에 vacuous 테스트가 생긴다.

before는 재캡처 경로가 없어 영향받지 않는다.

### 5. 요소가 여러 개일 때

diff table은 **요소마다 한 벌**이다(현재 선택 요소 + 버퍼된 요소들). 각 테이블의 before/after는 서로 독립이다 — A 요소의 before에 주석해도 B 요소 카드는 그대로다.

### 6. 저장·재개

- 주석한 상태로 패널을 닫았다 열면 주석이 유지된다(세션 스냅샷).
- `[다음]`으로 초안을 확정하면 **주석본이 저장된다**. 그 초안을 나중에 상세에서 열면 주석본이 보이지만 거기서 제거·재주석은 못 한다(비목표).
- 세션 스토리지 쿼터 초과로 lite 강등이 일어나면 이미지가 전부 빠지므로 주석본도 함께 사라진다 — 경로는 기존 동작과 같지만 **잃는 것의 성격이 다르다**. 기존엔 "다시 찍으면 되는 캡처"였고 이제는 "손으로 그린 주석"이다. 강등은 무음(`.catch(() => {})`)이라 사용자에게 알리지 않는다 — 이번 스코프에서는 수용하고 위험 요소에 기록한다.

### 7. 이미지가 없는 칸

캡처가 생략된 칸(`styleTable.noSnapshot`)에는 버튼이 없다. 주석할 대상이 없다.

### 8. AI 초안

AI 초안 생성 시 element 모드는 before/after를 LLM에 첨부한다(`getModeImages`). 여기도 **주석본을 보낸다** — 같은 함수의 screenshot 분기가 이미 `screenshotAnnotated ?? screenshotRaw`이고, 사용자가 손으로 지목한 곳을 모델이 못 보면 초안 품질이 떨어진다. 사용자가 그린 주석이 LLM으로 나가는 **새 전송**이므로 `docs/privacy.{ko,en}.md` 대조 대상이다.

## 성공 기준

- before·after 각 이미지에 hover하면 액션 버튼이 뜨고, 주석 유무에 따라 `[주석 추가]` / `[주석 제거][주석 수정]`로 갈린다.
- 주석 후 diff table 이미지가 주석본으로 바뀌고, 제거하면 원본으로 돌아간다.
- **2회 주석 후 `[주석 제거]`를 누르면 최초 원본으로 돌아간다**(직전 주석본이 아니라).
- 요소가 2개 이상일 때 각 카드의 주석이 서로 섞이지 않는다.
- 제출된 이슈의 `before-{i}.webp`/`after-{i}.webp`가 주석본이다.
- `PreviewPanel`의 diff table과 AI 초안에 첨부되는 이미지도 주석본이다.
- after 재캡처 후 그 카드의 after 주석이 사라져 있다. 세션 복원 왕복(`rebindStylingSession`)에서는 사라지지 않는다.
- `PreviewPanel`·`DraftDetailDialog`에는 버튼이 렌더되지 않는다.
- 패널을 닫았다 열어도 주석이 유지된다.
- 초안을 확정하고 상세에서 다시 열면 diff table에 주석본이 보인다.
- 요소 2개의 before/after 네 장을 모두 주석한 세션이 lite 강등 없이 패널 재오픈 후 복원된다. 단 이 승인선은 **캡처 크기 조건부**다 — 아래 조건을 함께 명시한다.
- Tab 키로 이미지 액션에 진입하면 버튼 그룹이 노출되고, 각 버튼의 접근명이 읽힌다. **보이지 않는 상태에서는 탭 정지점이 되지 않는다.**
- 스크린 리더가 before 칸과 after 칸의 이미지를 구분해 읽는다.
- 주석 오버레이는 다이얼로그로 식별되고 Escape로 취소할 수 있으며, 닫힌 뒤 포커스가 실행 버튼으로 돌아온다. 이 보강이 `DraftEditDialog` 안에서 열리는 인라인 이미지 주석을 깨뜨리지 않는다.

**쿼터 승인선의 조건**: element 크롭에는 픽셀 캡이 없어(`capture.ts`가 DPR·페이지 줌을 그대로 흡수) 요소당 이미지 크기가 250KB~5.6MB로 흔들린다. 따라서 승인선은 "요소 2개"가 아니라 **조상 컨테이너 확장 상한(뷰포트 면적 40%) × DPR 2 × 요소 2개**로 읽는다. 이 조건에서 실패하면 압축 대신 `capture.ts` 크롭에 `stitchGeometry`와 동일한 sqrt 픽셀 캡을 적용한다.
