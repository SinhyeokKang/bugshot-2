# diff table before/after 이미지 어노테이션

## 배경

element 모드로 잡은 버그는 리포트에서 **before/after 스냅샷 한 쌍**으로 전달된다. 그런데 이 두 장에는 지금 주석을 달 수 없다 — 확장 안에서 주석이 가능한 이미지는 스크린샷 캡처본(`screenshotRaw`)과 본문에 삽입한 인라인 이미지뿐이다.

문제는 element 캡처가 **가장 주석이 필요한 이미지**라는 점이다. 캡처 범위가 요소 bbox+24px이거나 의미 단위 조상 컨테이너라, 이미지 안에 요소가 여러 개 들어간다(다이얼로그·테이블 행·리스트 아이템). "이 버튼의 padding이 문제"라는 걸 이미지만으로는 지목할 수 없어서, 지금은 diff table의 prop 행을 읽어야만 어디를 봐야 하는지 알 수 있다. 리포트를 받는 사람(개발자·디자이너)이 이미지를 먼저 보는 순서와 어긋난다.

주석 기능 자체는 이미 있다(`AnnotationOverlay` — Konva 캔버스, 도형·텍스트·줌/팬). 진입점만 없다.

## 목표

- element 모드 drafting에서 diff table의 **before 이미지와 after 이미지 각각**에 주석을 달 수 있다.
- 주석을 단 뒤에도 **원본으로 되돌릴 수 있다**(초기화).
- 이슈로 제출되는 이미지는 주석본이다 — 받는 사람이 별도 조작 없이 주석을 본다.
- 주석 UI는 본문 인라인 이미지의 것과 **시각적으로 같다**. 사용자가 두 번 배우지 않는다.

## 비목표 (Non-goals)

- **저장된 초안 상세(`DraftDetailDialog`)·미리보기(`PreviewPanel`)에서의 주석.** 두 화면도 같은 `StyleChangesTable`을 렌더하지만 읽기 전용으로 남긴다. 스크린샷 주석(`annotation-edit`)이 `DraftingPanel` 전용인 것과 같은 급이다. (**주의**: 인라인 이미지 주석은 `TiptapEditor`가 `DraftEditDialog`에서도 마운트돼 저장된 초안에서도 열린다 — 이 기능은 그보다 좁은 범위다.)
- **주석 원본을 이슈에 함께 첨부하기.** 올라가는 건 주석본 한 장뿐이다.
- **주석 좌표의 재캡처 추종.** after가 다시 찍히면 주석은 버린다(아래 시나리오 4).
- **주석 데이터(도형 목록) 보관.** 결과 이미지만 남긴다 — 인라인 이미지·스크린샷과 동일하게 "주석 후 이미지를 다시 열면 그림 위에 이어 그린다".
- 버퍼 카드(`StyleChangesDialog`)의 행 초기화 UI 변경.

## 사용자 시나리오

### 1. before 이미지에 주석 (기본 플로우)

1. element 모드로 요소를 고르고 스타일을 수정한 뒤 `[다음]`으로 drafting에 들어온다.
2. `변경 사항 (selector)` 섹션의 diff table 첫 행에 before/after 스냅샷 두 장이 있다.
3. before 이미지에 마우스를 올리면 우상단에 `[연필]` 버튼이 나타난다.
4. 누르면 주석 오버레이가 뜬다(본문 인라인 이미지와 같은 화면).
5. 화살표를 그리고 `[완료]`를 누르면 오버레이가 닫히고 diff table의 before 이미지가 주석본으로 바뀐다.
6. 다시 마우스를 올리면 버튼이 `[초기화][연필]` 두 개다.

### 2. 주석 초기화

1. 주석이 있는 이미지에 마우스를 올려 `[초기화]`를 누른다.
2. 이미지가 즉시 원본으로 돌아가고 버튼이 `[연필]` 하나로 줄어든다.
3. 확인 다이얼로그는 없다 — 다시 주석하면 되고, 스크린샷 주석 제거(`annotation-remove`)도 즉시 실행이다.

### 3. 재주석 (주석 위에 이어 그리기)

1. 주석이 있는 이미지의 `[연필]`을 누른다.
2. 오버레이는 **주석본**을 배경으로 연다(원본이 아니다). 스크린샷 주석의 `screenshotAnnotated ?? screenshotRaw`와 같은 규칙.
3. 도형을 더 그려 `[완료]`하면 그 결과가 새 주석본이 된다. 원본은 그대로 보관돼 `[초기화]`는 여전히 최초 원본으로 되돌린다.

### 4. after 재캡처 — 주석 폐기

after 이미지는 사용자가 스타일을 더 고치면 다시 찍힌다. 재캡처 지점 셋:

- `StyleEditorPanel`에서 스타일 수정 후 `[다음]` (`setAfterImage`)
- 버퍼 카드의 행 초기화 후 재캡처 (`patchBufferedElement({ afterImage })`)
- drafting에서 `[뒤로]`로 styling에 복귀 (`backToStyling` — `afterImage: null`)

이 셋 모두에서 **after 주석을 함께 버린다**. 새로 찍힌 픽셀 위에 옛 좌표의 화살표가 남으면 엉뚱한 곳을 가리키고, 그건 주석이 없는 것보다 나쁘다. 사용자는 다시 주석해야 한다. before는 재캡처 경로가 없어 영향받지 않는다.

### 5. 요소가 여러 개일 때

diff table은 **요소마다 한 벌**이다(현재 선택 요소 + 버퍼된 요소들). 각 테이블의 before/after는 서로 독립이다 — A 요소의 before에 주석해도 B 요소 카드는 그대로다.

### 6. 저장·재개

- 주석한 상태로 패널을 닫았다 열면 주석이 유지된다(세션 스냅샷).
- `[다음]`으로 초안을 확정하면 **주석본이 저장된다**. 그 초안을 나중에 상세에서 열면 주석본이 보이지만 거기서 초기화·재주석은 못 한다(비목표).
- 세션 스토리지 쿼터 초과로 lite 강등이 일어나면 이미지가 전부 빠지므로 주석본도 함께 사라진다 — 기존 동작과 같다.

### 7. 이미지가 없는 칸

캡처가 생략된 칸(`styleTable.noSnapshot`)에는 버튼이 없다. 주석할 대상이 없다.

## 성공 기준

- before·after 각 이미지에 hover하면 액션 버튼이 뜨고, 주석 유무에 따라 `[연필]` / `[초기화][연필]`로 갈린다.
- 주석 후 diff table 이미지가 주석본으로 바뀌고, 초기화하면 원본으로 돌아간다.
- 요소가 2개 이상일 때 각 카드의 주석이 서로 섞이지 않는다.
- 제출된 이슈의 `before-{i}.webp`/`after-{i}.webp`가 주석본이다.
- after 재캡처 후 그 카드의 after 주석이 사라져 있다.
- `PreviewPanel`·`DraftDetailDialog`에는 버튼이 렌더되지 않는다.
- 패널을 닫았다 열어도 주석이 유지된다.
