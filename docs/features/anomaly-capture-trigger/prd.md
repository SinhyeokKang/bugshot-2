# 자동 버그 감지 트리거 (anomaly capture trigger)

## 배경

30s Replay는 이미 최근 30초의 화면 프레임을 상시 버퍼링하고 있고, console·network 레코더는 사이드패널이 열려 있는 동안 항상 로그를 쌓는다. 그런데 **"지금 리포트해야 한다"는 판단은 전적으로 사람이 한다.** 버그가 눈앞을 지나가고 나서야 "아, 캡처 누를걸"이 되는 구멍이 정확히 여기 하나 남아 있다.

버그가 발생한 사실 자체는 이미 기계가 알고 있다:

| 신호 | 현재 코드 위치 | 상태 |
|---|---|---|
| uncaught error | `content/console-recorder.ts:246` `window.addEventListener("error")` | 수집 중, 사용 안 함 |
| unhandled rejection | `content/console-recorder.ts:265` | 수집 중, 사용 안 함 |
| 5xx 응답 | `NetworkRequest.status` | 수집 중, 사용 안 함 |
| 네트워크 실패·타임아웃 | `NetworkRequest.phase === "error"` | 수집 중, 사용 안 함 |

즉 **새로 수집할 데이터가 없다.** 이미 손에 쥔 신호를 읽어 사용자에게 먼저 말을 걸어주는 것이 이 기능의 전부다. 새 권한·새 env·새 외부 요청은 하나도 늘지 않는다.

### 무엇을 구제하고 무엇을 못 구제하나

레코더는 `useBackgroundRecorder`가 사이드패널 마운트에 묶여 주입하고, 리플레이 폴링은 `use30sReplay`가 `enabled` + `tab.active`에서만 돈다. 따라서 이 기능이 구제하는 대상은 **"BugShot을 안 켠 사람"이 아니라 "켜뒀는데 캡처 버튼을 안 누른 사람"** 이다. QA·도그푸딩 세션에서는 그게 대부분의 시간이므로 유효하지만, 이 경계를 넘어서는 표현(사용자 문구·가이드·스토어 설명)을 쓰지 않는다.

## 목표

1. 리플레이 버퍼 구간(최대 30초) 안에서 발생한 uncaught error·unhandled rejection·5xx·네트워크 실패를 **캡처 진입 화면의 배지**로 알린다.
2. 배지를 누르면 **감지 내역 다이얼로그**가 열려 무엇이 감지됐는지 확인할 수 있다.
3. 다이얼로그의 [이슈 작성 시작]을 누르면 리플레이가 캡처되고, **감지 구간에 맞춰 자동으로 잘린 뒤**(앞뒤 3초 버퍼) 작성 화면으로 진입한다.
4. 작성 화면 진입과 동시에 **AI 초안이 사용자 입력 없이 자동 실행**된다. 감지된 오류가 곧 맥락이므로 사용자가 상황을 다시 설명할 필요가 없다.
5. 같은 오류가 반복돼도 배지 카운트는 **오류 종류 수**를 센다(루프 안 에러 500회 = 1건).
6. 페이지와 무관한 서드파티 오류로 배지가 상시 켜지지 않는다.

## 비목표 (Non-goals)

- **rage click·dead click 감지.** rage click은 오탐(스테퍼·좋아요·페이지네이션 연타)이 구조적이고, dead click은 `MutationObserver` 신규 후크가 필요한데 SPA 상시 리렌더 때문에 precision이 최악이다. 둘 다 이번 스코프에서 제외한다.
- **`console.error()` 호출을 신호로 쓰기.** 정상 운영 로그로 `console.error`를 쓰는 앱이 많아 배지가 상시 켜진다.
- **4xx 감지.** 401·403·404·422는 의도된 실패인 경우가 많다.
- **감지 항목 개별 선택.** 다이얼로그 목록은 읽기 전용이다. 항목별 체크박스로 로그·본문 범위를 좁히는 것은 기존 `logsAttach`·트림 경로와 겹쳐 범위가 크게 늘어난다.
- **감지 전용 설정 토글.** `replayEnabled`에 종속시키고 설정 항목을 늘리지 않는다.
- **감지 결과를 이슈 본문에 직접 프리필.** AI 초안 프롬프트로만 흘려보낸다.
- **PostHog 신규 이벤트.** 기존 `issue_submitted`에 속성 하나만 추가한다.
- **사이드패널이 닫힌 상태의 감지.** 레코더·버퍼가 패널에 묶여 있어 구조적으로 불가능하다.

## 사용자 시나리오

### 주 시나리오 — 놓친 버그를 잡는다

1. 사용자가 BugShot 사이드패널을 열어둔 채 웹 앱을 쓴다. 30s Replay는 on(신규 설치 기본값).
2. 페이지에서 `GET /api/orders`가 500을 뱉고 콘솔에 `TypeError: Cannot read properties of undefined`가 찍힌다. 사용자는 화면이 이상한 걸 눈치채지만 캡처 버튼은 누르지 않았다.
3. 1.5초 안에 캡처 진입 화면 상단에 배지가 뜬다 — **"감지된 오류 2건"**.
4. 배지를 누르면 다이얼로그가 열린다.
   ```
   감지된 오류
   ─────────────────────────────────
   ⚠  TypeError: Cannot read properties of undefined      12:31:04
   ⚠  GET /api/orders → 500                                12:31:04
   ─────────────────────────────────
              [닫기]  [이슈 작성 시작]
   ```
5. [이슈 작성 시작] → 리플레이가 인코딩되고, 감지 구간(첫 오류 −3초 ~ 마지막 오류 +3초)으로 **조용히** 잘린 영상과 그 구간으로 좁혀진 로그가 붙는다. 트림 다이얼로그는 뜨지 않는다.
6. 작성 화면으로 진입하면서 AI 초안 오버레이가 곧바로 뜬다. 사용자는 아무것도 입력하지 않았다.
7. 제목·설명·재현 단계가 채워진 초안이 나온다. 사용자는 검토 후 제출한다.

### 엣지 케이스

| 상황 | 동작 |
|---|---|
| 30s Replay 설정 off | 배지가 뜨지 않는다. 감지 자체를 돌리지 않는다. |
| 버퍼가 아직 `MIN_READY_FRAMES`(10프레임) 미만 | 배지가 뜨지 않는다. 캡처가 불가능한 동안 배지를 띄우면 눌러도 아무 일이 안 일어난다. |
| 감지된 오류가 버퍼 창(최대 30초) 밖으로 밀려남 | 카운트에서 빠진다. 전부 빠지면 배지가 사라진다. |
| 같은 오류가 500회 반복 | 시그니처 1건. 다이얼로그에도 한 줄. |
| 감지 로그가 1건뿐(span 0) | 앞뒤 3초씩 총 6초 클립. |
| 감지 구간이 버퍼 전체를 덮음 | `applyReplayTrim`의 `isFullRange` 판정에 걸려 재인코딩을 건너뛴다(원본 유지). |
| AI 미가용(BYOK 없고 Chrome Nano도 불가) | AI 초안을 실행하지 않는다. 재현 단계 자동 채움도 AI가 필요하므로 함께 불가 → 평소대로 빈 작성 화면. |
| AI 초안이 실패(quota·빈 응답·중단) | 기존 재현 단계 자동 채움(`useReproPrefill`)이 대신 발화한다. |
| 미지원 페이지(chrome:// 등) | 로그가 쌓이지 않고 리플레이도 suspend라 감지 0. |
| 페이지가 다른 도메인으로 이동 | 새 페이지 도메인 기준으로 재판정. 이전 도메인 오류는 카운트에서 빠진다. |
| 작성 중(phase ≠ idle) | 배지는 캡처 진입 화면에만 있으므로 보이지 않는다. |

## 성공 기준

- 리플레이 버퍼 구간에서 uncaught error 또는 5xx가 발생하면 1.5초 이내에 배지가 뜬다.
- 같은 오류를 반복 발생시켜도 배지 카운트가 1로 유지된다.
- 페이지와 다른 registrable domain의 오류만 발생하면 배지가 뜨지 않는다.
- `statusText === "Aborted"`인 요청만 발생하면 배지가 뜨지 않는다.
- [이슈 작성 시작] → 트림 다이얼로그 없이 drafting으로 진입하고, 첨부 영상 길이가 감지 span + 6초 근처다.
- 진입 직후 AI 초안 로딩 오버레이가 뜨고, 완료 후 초안이 채워져 있다.
- `replayEnabled`가 off면 어떤 오류를 내도 배지가 뜨지 않는다.
- 감지 경로로 제출한 이슈의 `issue_submitted`에 `from_anomaly: "true"`가 실린다.
