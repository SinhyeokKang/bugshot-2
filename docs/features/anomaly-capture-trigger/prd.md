# 자동 버그 감지 트리거 (anomaly capture trigger)

## 배경

30s Replay는 이미 최근 30초의 화면 프레임을 상시 버퍼링하고 있고, console·network 레코더는 사이드패널이 열려 있는 동안 항상 로그를 쌓는다. 그런데 **"지금 리포트해야 한다"는 판단은 전적으로 사람이 한다.** 버그가 눈앞을 지나가고 나서야 "아, 캡처 누를걸"이 되는 구멍이 정확히 여기 하나 남아 있다.

버그가 발생한 사실 자체는 이미 기계가 알고 있다:

| 신호 | 현재 코드 위치 | 상태 |
|---|---|---|
| uncaught error | `content/console-recorder.ts:246` `window.addEventListener("error")` | 수집 중, 사용 안 함 |
| unhandled rejection | `content/console-recorder.ts:264` | 수집 중, 사용 안 함 |
| 5xx 응답 | `NetworkRequest.status` | 수집 중, 사용 안 함 |
| 네트워크 실패·타임아웃 | `NetworkRequest.phase === "error"` | 수집 중, 사용 안 함 |

즉 **새로 수집할 데이터가 없다.** 이미 손에 쥔 신호를 읽어 사용자에게 먼저 말을 걸어주는 것이 이 기능의 전부다. 새 권한·새 env·새 외부 요청은 하나도 늘지 않는다.

### 무엇을 구제하고 무엇을 못 구제하나

레코더는 `useBackgroundRecorder`가 사이드패널 마운트에 묶여 주입하고, 리플레이 폴링은 `use30sReplay`가 `enabled` + `tab.active`에서만 돈다. 여기에 알림 표면의 제약이 하나 더 있다:

- 배지는 **캡처 진입 화면(`EmptyState`)에만** 있고, `IssueTab`은 `forceMount` 없는 Radix `TabsContent`라 **console/network 서브탭을 보는 동안 통째로 언마운트**된다 → 그동안 감지가 멈춘다.
- network 5xx는 응답 갱신 시 자체 dispatch를 하지 않고(`content/network-recorder.ts:596-599`) `DebugTab.tsx:46-59`의 1500ms 강제 sync에 의존하는데, 그 sync는 `activeMainTab === "debug" && sub === "issue"`에서만 돈다.

따라서 이 기능이 구제하는 대상은 **"BugShot을 안 켠 사람"이 아니라 "켜두고 Debug>이슈 화면에 머물러 있는데 캡처 버튼을 안 누른 사람"** 이다. QA·도그푸딩 세션에서는 그게 대부분의 시간이므로 유효하지만, 이 경계를 넘어서는 표현(사용자 문구·가이드·스토어 설명)을 쓰지 않는다.

## 목표

1. 리플레이 버퍼 구간(최대 30초) 안에서 발생한 uncaught error·unhandled rejection·5xx·네트워크 실패를 **캡처 진입 화면의 배지**로 알린다.
2. 배지를 누르면 **감지 내역 다이얼로그**가 열려 무엇이 감지됐는지 확인할 수 있다.
3. 다이얼로그의 [이슈 작성]을 누르면 리플레이가 캡처되고, **감지 구간에 맞춰 자동으로 잘린 뒤**(앞뒤 3초 버퍼) 작성 화면으로 진입한다.
4. 작성 화면 진입과 동시에 **AI 초안이 사용자 입력 없이 자동 실행**된다. 감지된 오류가 곧 맥락이므로 사용자가 상황을 다시 설명할 필요가 없다.
5. 같은 오류가 반복돼도 배지 카운트는 **중복 제거된 감지 신호 종류 수**를 센다(루프 안 에러 500회 = 1종).
6. 페이지와 무관한 서드파티 오류로 배지가 상시 켜지지 않는다.
7. **`replayEnabled` 기본값을 `false` → `true`로 바꾼다.** 감지가 리플레이 버퍼에 종속되므로 기본이 off인 채로는 기능이 아무에게도 도달하지 않는다. 이 항목의 실제 영향 범위·리스크는 아래 별도 절에 기술한다.

### `replayEnabled` 기본값 변경 (목표 7 상세)

이 저장소 최초의 기본값 뒤집기이고, 30s Replay는 **privacy 문서 미갱신으로 웹스토어 심사에서 한 번 탈락한 바로 그 기능**이다. 따라서 영향 범위를 정확히 적어둔다.

`settings-ui-store`는 `partialize`가 없어 **전체 state를 persist**하고, `merge`는 `{...current, ...persisted}`라 저장값이 새 기본값을 이긴다. 결과적으로 사용자군이 셋으로 갈린다:

| 사용자군 | storage 상태 | 변경 후 |
|---|---|---|
| 신규 설치 | 엔트리 없음 | **on** |
| 설정을 한 번도 바꾼 적 없는 기존 사용자 | 엔트리 없음 | **조용히 on으로 바뀐다** |
| 설정을 한 번이라도 바꾼 기존 사용자 | `replayEnabled: false`가 저장돼 있음 | off 유지 |

즉 **"기존 사용자 무영향"이 아니다.** 두 번째 군에서 600ms 간격 `captureVisibleTab` 폴링이 사용자 동의 없이 켜진다. 그래서:

- `docs/privacy.ko.md`·`.en.md` 양쪽 본문 + 상단 시행일 갱신을 **필수 게이트**로 둔다. 현재 privacy 문서는 리플레이 프레임 수집을 "30초 리플레이 활성화 시"라는 조건부 수집으로 기술하므로, 기본값이 뒤집히면 그 문장이 사실과 어긋난다.
- `migrate` 분기는 추가하지 않는다 — "미설정"과 "명시적 off"를 구분할 수단이 현재 구조에 없고, 새 플래그(`replayOptOut`)를 도입하는 것은 이 스코프에서 과하다.

## 비목표 (Non-goals)

- **rage click·dead click 감지.** rage click은 오탐(스테퍼·좋아요·페이지네이션 연타)이 구조적이고, dead click은 `MutationObserver` 신규 후크가 필요한데 SPA 상시 리렌더 때문에 precision이 최악이다. 둘 다 이번 스코프에서 제외한다.
- **`console.error()` 호출을 신호로 쓰기.** 정상 운영 로그로 `console.error`를 쓰는 앱이 많아 배지가 상시 켜진다.
- **4xx 감지.** 401·403·404·422는 의도된 실패인 경우가 많다.
- **감지 항목 개별 선택.** 다이얼로그 목록은 읽기 전용이다. 항목별 체크박스로 로그·본문 범위를 좁히는 것은 기존 `logsAttach`·트림 경로와 겹쳐 범위가 크게 늘어난다.
- **감지 전용 설정 토글.** `replayEnabled`에 종속시키고 설정 항목을 늘리지 않는다.
- **감지 결과를 이슈 본문에 직접 프리필.** AI 초안 프롬프트로만 흘려보낸다.
- **PostHog 신규 이벤트.** 기존 `issue_submitted`에 속성 하나만 추가한다.
- **사이드패널이 닫힌 상태의 감지.** 레코더·버퍼가 패널에 묶여 있어 구조적으로 불가능하다.
- **캡처 진입 화면 밖의 알림 표면.** 탭 헤더 dot·배지 등으로 다른 탭에서도 감지를 알리는 것은 이번 스코프가 아니다. 감지 훅을 `IssueTab` 밖으로 올려야 하고 `TabsContent` 언마운트 문제를 별도로 풀어야 한다 — 위 "무엇을 구제하고 무엇을 못 구제하나"의 경계를 그대로 수용한다.

## 사용자 시나리오

### 주 시나리오 — 놓친 버그를 잡는다

1. 사용자가 BugShot 사이드패널을 열어둔 채 웹 앱을 쓴다. 30s Replay는 on(기본값), Debug>이슈 화면에 머물러 있다.
2. 페이지에서 `GET /api/orders`가 500을 뱉고 콘솔에 `TypeError: Cannot read properties of undefined`가 찍힌다. 사용자는 화면이 이상한 걸 눈치채지만 캡처 버튼은 누르지 않았다.
3. 1.5초 안에 캡처 진입 화면의 제목 아래·캡처 버튼 열 위에 배지가 뜬다 — **"감지 신호 2종"**.
4. 배지를 누르면 다이얼로그가 열린다. 각 행은 2행 스택이다(사이드패널 폭에서 3컬럼 한 줄은 메시지가 잘려 읽히지 않는다 — 아래 "레이아웃 제약" 참조).
   ```
   감지된 오류
   ─────────────────────────────────
   ⚠  TypeError: Cannot read properties…
      12:31:04 · console
   ⚠  GET /api/orders → 500
      12:31:04 · network
   ─────────────────────────────────
              [닫기]  [이슈 작성]
   ```
5. [이슈 작성] → 리플레이가 인코딩되고, 감지 구간(첫 오류 −3초 ~ 마지막 오류 +3초)으로 **조용히** 잘린 영상과 그 구간으로 좁혀진 로그가 붙는다. 트림 다이얼로그는 뜨지 않는다. 실제로 구간이 잘린 경우에만 작성 화면 진입 후 "오류 구간 앞뒤 3초로 잘라 첨부했습니다" 토스트가 사후 고지한다.
6. 작성 화면으로 진입하면서 AI 초안 오버레이가 곧바로 뜬다. 사용자는 아무것도 입력하지 않았다.
7. 제목·설명·재현 단계가 채워진 초안이 나온다. 사용자는 검토 후 제출한다.

### 레이아웃 제약

사이드패널 다이얼로그는 `w-[90vw]`이고 `max-w-[800px]`는 사이드패널 폭에서 절대 발동하지 않는다(≥889px 필요). `p-6`을 빼면 실제 콘텐츠 폭은 320px 패널에서 **240px**, 400px 패널에서 **312px**다. 아이콘·gap·시각을 제하면 한 줄에 남는 메시지 폭이 320px에서 118px까지 줄어 `GET /api/orders → 500`조차 status가 사라진다. 그래서 3컬럼 한 줄이 아니라 **2행 스택 + 메시지 2줄 표시 + 넘칠 때 Radix Tooltip**을 쓴다. 320×400처럼 낮은 패널에서는 중앙 영역만 세로 스크롤한다.

### 엣지 케이스

| 상황 | 동작 |
|---|---|
| 30s Replay 설정 off | 배지가 뜨지 않는다. 감지 자체를 돌리지 않는다. |
| 버퍼가 아직 `MIN_READY_FRAMES`(10프레임) 미만 | 배지가 뜨지 않는다. 캡처가 불가능한 동안 배지를 띄우면 눌러도 아무 일이 안 일어난다. |
| 감지된 오류가 버퍼 창(최대 30초) 밖으로 밀려남 | 카운트에서 빠진다. 전부 빠지면 배지가 사라진다. |
| 같은 오류가 500회 반복 | 시그니처 1건. 다이얼로그에도 한 줄. |
| 같은 시그니처가 버퍼 경계에 걸침(앞쪽만 밀려남) | `timestamp`를 창 안 최초 발생으로 갱신한다. |
| 감지 로그가 1건뿐(span 0) | 앞뒤 3초씩 총 6초 클립. |
| 감지 구간이 버퍼 전체를 덮음 | `applyReplayTrim`의 `isFullRange` 판정에 걸려 조기 반환한다 — 재인코딩뿐 아니라 **로그 재trim도 건너뛰고 `videoTrimmed`도 false로 남는다**. |
| 시그니처 종류가 과다(예: 100종) | 다이얼로그 목록에 상한을 두고(상위 20종) 나머지는 "외 N종"으로 접는다. 목록 영역은 `max-h-[80vh]` 안에서 스크롤. |
| 감지 시각이 미래(시계 역행) | `windowStart > now`면 빈 배열. |
| 탭이 비활성이었다가 복귀 | 폴링·로그가 멈춰 있었으므로 감지 창(`bufferOldestTs`~now)이 실제 버퍼보다 넓어 보인다. 창 판정은 프레임 타임스탬프 기준이므로 잘못된 신호는 섞이지 않는다. |
| 인코딩 진행 중 배지 클릭 | phase는 여전히 `idle`이라 배지가 눌리지만 `capture()`가 `encodingRef` 가드로 no-op이 된다. 배지 버튼에도 `isEncoding` 가드를 걸어 비활성화한다(`ReplayButton` 선례). |
| 다이얼로그가 열린 채 신호가 창 밖으로 밀림 | 다이얼로그는 open 시점의 signals를 **스냅샷 고정**하고 이후 갱신을 무시한다. 추가로 `capture()` 안에서 로그 trim 후 남은 신호로 재필터해 프롬프트와 첨부 로그가 어긋나지 않게 한다. |
| [이슈 작성] 시 재필터 결과가 0건 | 캡처를 시작하지 않고 다이얼로그에 "오류 구간이 만료되었습니다" 상태를 표시한다. |
| 자동 트림 중 사이드패널 종료 | 재개할 프레임이 없으므로 anomaly 세션을 폐기한다. 원본 영상은 유지하고 감지 신호·자동 AI·`from_anomaly` 계측을 제거해 일반 작성 화면으로 복구한다. |
| 다이얼로그가 열린 채 phase 전이(picker 시작 등) | 다이얼로그가 닫힌다. |
| AI 미가용(BYOK 없고 Chrome Nano도 불가) | AI 초안을 실행하지 않는다. 재현 단계 자동 채움도 AI가 필요하므로 함께 불가 → 평소대로 빈 작성 화면. |
| AI 초안이 실패(quota·빈 응답) | 기존 재현 단계 자동 채움(`useReproPrefill`)이 대신 발화한다. |
| AI 초안을 사용자가 **중단** | 기존 AI 초안 중단 배선을 그대로 타고 빈 이슈 작성 폼으로 돌아간다. `anomalyDraftDone`만 세우며 AI 초안 재시도와 재현 단계 자동 채움은 실행하지 않는다. |
| `logsAttach` off + AI 미가용 | 감지로 만든 이슈인데 오류 흔적이 본문에 0건이 된다. 이 조합에서는 감지 내역 한 줄을 `description`에 넣는 대신, **다이얼로그에서 [이슈 작성] 시 `logsAttach`가 off면 배지 툴팁/다이얼로그 설명에 "로그 첨부가 꺼져 있어 오류 내역이 본문에 남지 않습니다"를 고지**한다. 본문 프리필은 여전히 비목표. |
| 미지원 페이지(chrome:// 등) | `useTabUnsupported` 판정으로 배지 게이트(`!unsupported`)가 닫혀 감지 0. (리플레이 suspend는 버퍼를 비우지 않고 `isReady`도 true로 남으며 로그도 cross-page 누적이므로, suspend가 이유가 아니다.) |
| 페이지가 다른 도메인으로 이동 | 새 페이지 도메인 기준으로 재판정. 이전 도메인 오류는 카운트에서 빠진다. |
| `pageUrl`이 `about:blank`·`file:` | registrable domain을 뽑을 수 없으므로 감지 0(전부 차단). |
| WebSocket 엔트리(`status: 101`, `method: "WS"`) | `phase: "error"`로 끝나도 감지하지 않는다 — 정상 종료와 구분이 안 된다. |
| 작성 중(phase ≠ idle) | 배지는 캡처 진입 화면에만 있으므로 보이지 않는다. |
| console/network 서브탭을 보는 중 | `TabsContent` 언마운트로 감지가 멈춘다. 서브탭 복귀 시 재판정된다. |

## 성공 기준

### 동작

- **Debug>이슈 화면에 머무는 상태에서** 리플레이 버퍼 구간에 uncaught error가 발생하면 1.5초 이내에 배지가 뜬다. (network 5xx는 `DebugTab`의 1500ms 강제 sync에 의존하므로 최대 3초까지 늦을 수 있다.)
- 같은 오류를 반복 발생시켜도 배지 카운트가 1로 유지된다.
- 페이지와 다른 registrable domain의 오류만 발생하면 배지가 뜨지 않는다.
- 사용자가 취소한 요청(XHR abort·fetch AbortError)만 발생하면 배지가 뜨지 않는다.
- [이슈 작성] → 트림 다이얼로그 없이 drafting으로 진입하고, 첨부 영상 길이가 감지 span + 6초 근처다.
- 느린 요청은 요청 생명주기(`[startTime, startTime + durationMs]`)가 영상 구간과 겹치면 로그에 보존된다.
- 진입 직후 AI 초안 로딩 오버레이가 뜨고, 완료 후 초안이 채워져 있다.
- `replayEnabled`가 off면 어떤 오류를 내도 배지가 뜨지 않는다.
- 감지 경로로 제출한 이슈의 `issue_submitted`에 `from_anomaly: "true"`가 실린다.

### 기본값 변경

- 신규 프로필에서 `replayEnabled === true`.
- persist에 `replayEnabled: false`가 저장돼 있으면 복원 후에도 `false`.
- v9 미만 persist 객체(키 자체가 없음)를 `migrateSettingsUi`에 통과시키면 `true`가 된다 — 이것이 의도된 동작임을 테스트로 고정한다.

### 정확도

- 광고·분석 스크립트가 많은 상용 사이트 5개를 각 5분씩 사용했을 때, **사용자가 리포트할 의사가 전혀 없는 배지가 뜬 사이트 수가 2개 이하**다. 3개 이상이면 origin 게이트를 재설계하거나 기능 노출을 재검토한다.

### 계측 정합

- 자동 트림 경로가 `applyReplayTrim`을 타므로 `replay_trimmed`가 `true`, `trim_source`가 `"frames"`로 나간다 — 사용자가 직접 자른 것과 구분되지 않는다. `from_anomaly`와 교차해 읽어야 하며, 이 사실을 `docs/privacy.ko.md`의 "구간 자르기 사용률" 설명과 정합시킨다.
