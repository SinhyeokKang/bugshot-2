# 다중 요소 캡처

## 배경

요소 캡처는 현재 요소 하나를 찍으면 이슈 작성으로 이동하고, 다음 요소를 찍으려면 새 캡처를 시작해야 한다. 서로 떨어진 요소나 같은 요소의 다른 상태를 하나의 리포트에 담을 수 있어야 한다.

여기서 요소 캡처는 `captureMode: "screenshot"`으로 동작하는 진입 화면의 요소 캡처다. CSS 편집의 `captureMode: "element"`와 구분한다.

`DROPPED.md`의 2026-08-10 요소 식별 정보 표시 재설계는 재개하지 않는다. 번호 목록·스타일 표 참조 체계를 도입하지 않고 기존 재현 환경 엘리먼트(DOM) 행의 값만 선택 순서대로 누적한다. 이번 변경의 검증 기준은 캡처 목록과 출력의 일치다.

## 목표

- 최초 요소 선택 후 이슈 작성으로 진입하는 흐름을 유지한다.
- 작성 화면에서 요소를 추가 선택하면 기존 본문을 보존하고 미디어 끝에 새 캡처를 붙인다.
- 미디어 목록과 재현 환경 엘리먼트 행이 추가·삭제 순서를 함께 반영한다.
- 저장·복원·미리보기·제출·첨부 복구에서 캡처가 빠지거나 뒤바뀌지 않는다.

## 비목표 (Non-goals)

- 한 번의 피커 실행에서 여러 요소를 선택하는 방식, 체크박스·다중 선택 표시.
- 여러 요소를 한 이미지로 합성하거나 순서를 드래그로 바꾸는 기능.
- selector로 같은 요소를 판별하거나 중복 제거·기존 캡처 교체.
- 영역/화면/페이지 전체 캡처에 요소 추가 버튼을 노출하는 변경.
- CSS 편집 모드, 영상, 자유 작성의 미디어 모델 변경.
- 다른 탭의 요소를 한 리포트에 추가하는 기능, 새 권한·OAuth·서버 저장소.
- 이슈 본문 엘리먼트 행의 표시 형식 재설계.

## 사용자 시나리오

1. 요소 캡처 진입 → 요소 선택 → 이미지 한 장과 엘리먼트 정보가 있는 이슈 작성 화면.
2. 미디어 섹션 우상단 버튼 그룹의 가장 왼쪽에 진한 기본 스타일의 **요소 추가** 버튼을 둔다.
3. 버튼 클릭 → 같은 대상 탭의 피커 진입 → 요소 하나 선택 → 이슈 작성으로 복귀한다. 새 이미지는 기존 이미지 아래에 추가되고 엘리먼트 정보도 같은 순서로 누적된다.
4. 같은 요소를 다시 찍어도 별도 항목으로 추가한다. selector가 같더라도 목록과 엘리먼트 행에서 합치지 않는다.
5. 각 이미지 우상단에 주석 편집·다운로드·삭제 컨트롤을 항상 노출한다. 이미지 위 버튼 그룹은 불투명한 토큰 배경을 사용해 이미지 색과 무관하게 읽히게 한다. 주석 제거는 해당 항목에 주석이 있을 때만 표시한다.
6. 삭제는 팝오버·확인창 없이 해당 이미지와 연결된 엘리먼트 정보만 즉시 제거한다. 마지막 한 장에는 삭제 버튼을 숨기고 store에서도 삭제를 거부한다.
7. 추가 피커에서 취소하거나 캡처·주입·권한 확보에 실패하면 기존 본문·미디어·주석·플랫폼 선택·로그 설정을 유지한 작성 화면으로 돌아온다. 실패 안내는 기존 채널로 한 번만 제공한다.
8. 추가 선택 중 패널을 닫았다 열면 기존 작성 상태로 복원한다. 늦게 도착한 이전 캡처 결과는 무시한다. 다른 탭으로 캡처를 돌리지 않는다.
9. 작성 중 대상 탭이 다른 페이지로 이동했으면 요소 추가를 거부하고 원래 페이지로 돌아오도록 안내한다. 기존 보고서 URL과 자료는 유지한다. 원래 페이지로 돌아온 뒤 다시 추가할 수 있다.
10. 추가 성공 시 미디어 섹션을 펼쳐 새 이미지가 보이도록 이동한다. 취소·실패 시 기존 스크롤 위치와 요소 추가 버튼 포커스를 복원한다.
11. 미리보기, 저장 초안 상세, 제출 파일, 로그 HTML에서 남아 있는 이미지를 같은 순서로 확인한다. AI 초안에는 기존 이미지 수·토큰 예산을 적용하고 잘린 이미지는 기존 누락 안내에 포함한다.

## 성공 기준

- A → B → A를 선택하면 이미지 세 장과 엘리먼트 값 A, B, A가 생긴다. B 삭제 후 A, A가 남는다.
- 첫 장을 삭제해도 남은 장의 이미지·selector·주석이 서로 바뀌지 않는다.
- 마지막 한 장 삭제는 UI 및 상태 액션 양쪽에서 불가능하다.
- 제목·본문을 작성한 뒤 추가·취소·실패·재열기를 해도 작성 내용이 보존된다.
- 단일 캡처의 기존 저장 데이터와 제출 복구 journal을 계속 읽을 수 있다.
- 최초 제출과 저장 초안 재제출이 동일한 순서·내용의 이미지와 엘리먼트 행을 만든다.
- 첨부 일부 실패 후 재시도는 실패 파일만 처리하고 새 이슈를 만들지 않는다.
- 같은 저장 초안의 주석만 바꿔 다시 저장해도 열린 상세 화면이 새 이미지를 표시한다.
- 저장 도중 후속 이미지 쓰기나 메타 저장이 실패하면 이전 저장본의 이미지 바이트까지 보존한다.
- 추가 선택 중 페이지 이동과 패널 닫기가 겹쳐도 재열기 시 기존 작성 내용과 미디어가 복원된다.
- 저장/메시지 용량 초과를 이미지 누락이나 기존 초안 초기화로 처리하지 않는다. 추가 또는 제출을 거부하고 기존 자료를 보존한다.
- 캡처 데이터는 기존과 동일하게 사용자 브라우저에서 선택한 제출 대상 또는 LLM으로 직접 전송한다.

용량 초과 시 새 추가·주석 변경을 거부하고 마지막 정상 저장본을 보존한다. 이미지가 빠진 경량 스냅샷으로 정상 저장본을 덮지 않는다. 낮은 높이의 캡처도 액션의 32px 히트 영역과 이미지 확인 공간을 함께 확보한다.
